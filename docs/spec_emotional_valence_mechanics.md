# 开发需求规格文档：情绪效价（Emotional Valence）机制设计与双维度（E-T）调控方案

> **文档标识**：`SPEC-COMM-24-21-VALENCE-MECHANICS`  
> **所属模块**：沟通与人设系统 (`comm/`, `docs/mechanics/24-comm.md`, `defaults/comm_protocol.txt`)  
> **适用终端**：桌面端 (Python/tkinter) 与 安卓端 (Kotlin/Compose)

---

## 1. 机制背景与设计动机

### 1.1 现状与单一维度局限
在 OIT 当前的沟通机制中，已经具备了情绪张力（Tension，用 **T** 表示）系统。
- **当前 Tension (T) 的通用含义**：代表行为、动作与语言的**激烈 / 直接程度**（Arousal / Directness / Intensity）。
- **局限性**：由于只有 T 这一个标量维度，高张力容易被单一地表现为情绪过载、激烈冲突、审判质问或失控；而低张力则往往被单一地表现为平淡或克制。然而在实际的人际互动与角色扮演中，同一种高张力在不同情感基底下有着截然相反的表意：
  - 既可以是极度友好、炽热直白的暧昧告白与关切（正面 + 高张力）；
  - 也可以是惩罚性质、严厉问责与发泄式的训诫压迫（负面 + 高张力）。
  - 同理，在低张力下，既有温柔安心的抚慰（正面 + 低张力），也有委屈、吐槽与抱怨的低气压（负面 + 低张力）。

### 1.2 引入情绪效价（Valence，用 E 表示）
为了让角色的反应立体化、避免“高张力即失控攻击”的单一走向，引入与 Tension 架构并行的第二维度：**情绪效价（Emotional Valence，简称 Valence，用 E 表示）**。
- **情绪效价的定义**：从负面（Negative）到正面（Positive），区分烦躁、低落、委屈 vs 愉快、安心、眷恋等情感方向。
- **与 Tension (T) 协同构成的四象限模型**：

| 象限 | 维度组合 | 典型情感方向 | 言行与互动表现风格 |
| :--- | :--- | :--- | :--- |
| **第一象限** | **E+ T+** (高正效价 + 高张力) | 热情、炽热、极度直白、热切眷恋 | **友好 / 暧昧的直接表现**：大胆直接的情感袒露、直球关怀、带有占有欲或强保护欲的亲密表达。 |
| **第二象限** | **E- T+** (高负效价 + 高张力) | 愤怒、极度烦躁、严厉、审判 | **发泄 / 惩罚性质的直接表现**：尖锐问责、直接施压、严厉训诫、不留情面的情绪宣泄。 |
| **第三象限** | **E- T-** (高负效价 + 低张力) | 低落、委屈、倦怠、微烦 | **吐槽 / 抱怨性质的柔和表现**：冷淡阴阳、轻度吐槽、低气压叹气、委屈撒娇或幽怨碎碎念。 |
| **第四象限** | **E+ T-** (高正效价 + 低张力) | 平静、安心、温和、愉悦 | **友好 / 暧昧的柔和表现**：温和包容、安抚陪伴、柔声细语、含蓄克制的关切与默契。 |

## 2. 数值与状态模型设计（参考 Tension 机制）

情绪效价（Valence）的代码实现与调控架构全盘参考 Tension 的成熟设计，保持算法结构与时钟步调的一致性。

### 2.1 数值范围与中枢定义
- **符号表示**：`E`（Valence / 情绪效价）。
- **数值区间**：默认 `[-100.0, +100.0]`，保留浮点数小数位（对齐 Tension 保留小数的规则）。
- **默认中心值**：`0.0`（中立基准线）。新角色初始化或完全静置恢复后的默认值为 0.0。
- **档位划分**（用于系统提示词与档位映射）：
  - `E > +30.0`：**正效价区**（Positive / 偏正面）。
  - `-30.0 <= E <= +30.0`：**中立区**（Neutral / 平和）。
  - `E < -30.0`：**负效价区**（Negative / 偏负面）。
  - 极端状态：`|E| >= 70.0` 可标记为高正/高负强烈倾向区。

### 2.2 衰减与向中心靠拢机制（Decay Towards Zero）
情绪效价与 Tension 采用完全相同的时钟周期向基准靠拢，体现人类情绪随着时间推移自然趋于平复的生理心理规律。

1. **靠拢周期**：与 Tension 相同，**每 15 分钟（`COMM_TENSION_DECAY_SECONDS = 900s`）** 进行一次线性微调结算。
2. **靠拢方向**：**始终向中心点 0.0 靠拢**：
   - 当 `E > 0` 时，随时间线性衰减（扣减）；
   - 当 `E < 0` 时，随时间线性回升（增加）；
   - 当 `E == 0` 时，保持为 0，不再变动。
3. **靠拢速率**：
   - 参考基准速率：以每天平复约 50 点（即每 15 分钟结算 `50 / 96 ≈ 0.5208` 点）向 0 靠拢。
   - 步进计算公式（每次 15 分钟 tick）：
     $$\Delta E = \text{rate} \times \frac{\text{step}}{86400000}$$
     若 $E > 0$，则 $E = \max(0.0, E - \Delta E)$；  
     若 $E < 0$，则 $E = \min(0.0, E + \Delta E)$。
4. **离线跨天补算**：
   - 沿用 Tension 的 `decay_at` 绝对毫秒时间戳游标逻辑。重新启动或同步时，若距离上次结算已经过去多个 15 分钟，自动按步长逐段向 0.0 补算，不丢步、不提前透支。

## 3. 互动驱动与增减机制（与模型交互）

情绪效价的变化不依赖机械的硬编码正则，而是全权由人设文件声明规则、交由大模型在生成回复时根据语境理解判断。

### 3.1 模板定义语法 (`[valence]`)
在人设配套模板文件（如 `Claudia_templates.txt`）中增加类似 `[tension]` 的专用区块：

```text
[valence]
# 条件名:[参考基础变化量] 语义触发描述
# 正数表示向正面推动(E+)，负数表示向负面推动(E-)
gratitude:[+20] 用户真诚表达感激、肯定或温暖关怀
shared_joy:[+15] 用户分享成功、快乐或日常温馨趣事
comforting:[+25] 用户给予温柔安抚、体谅与情绪支持
provocation:[-25] 用户刻意挑衅、无理取闹或不尊重边界
frustration:[-15] 用户持续抱怨、消极摆烂或发泄负面情绪
hurt:[-30] 用户说出伤害信任、推开对方或冷酷自私的话语
custom_other:[X] 由模型根据上下文判断正负与变化幅度
[/valence]
```

- **参数约束**：
  - 条件名称限 1–32 个英文字符/下划线。
  - 参考基础变化量范围为 `[-40, +40]` 的非零整数。
  - 同样支持 `[X]` 不定量，交由模型根据语义动态裁定。

### 3.2 协议交互与结构化返回 (`oit_reply`)
在原生工具协议 `oit_reply` 中扩展效价字段，与张力字段并列：

```json
{
  "oit_reply": {
    "text": "回复正文...",
    "tension": [
      {"index": 0, "condition": "boundary", "gain": 20}
    ],
    "valence": [
      {"index": 0, "condition": "gratitude", "shift": 15}
    ]
  }
}
```
*(兼容旧版纯文本标记：`[valence:序号:条件:偏移量]`)*

### 3.3 结算与冷却规则
1. **独立 3 小时冷却窗口**：
   - 每个对象的 `interaction` 中独立记录 `valence_cooldowns`，格式为 `{condition_name: expire_ms}`。
   - 同一条件在 3 小时内仅能触发一次，防止刷屏导致数值极端漂移。
   - 成功加值或减值后才计入冷却；未达成增减、拒绝回复或在冷却中的条件不重复生效。
2. **结算上下限防越界**：
   - 任何加减结算后，强制约束在 `[-100.0, +100.0]` 闭区间内：`E = max(-100.0, min(100.0, E + shift))`。

## 4. 状态注入与提示词规范（Prompt Injection）

在向模型发起对话请求时，系统状态注入段（`[OIT_STATUS: ...]`）同步更新为双维度表示。

### 4.1 注入格式规范
```text
[OIT_STATUS: MODE=..., TENSION=..., EFFECTIVE_STAGE=..., VALENCE=..., BURST=..., PERIOD=..., SHAME_AFTERMATH=...]
```
- 新增 `VALENCE=<当前E浮点数值>`。
- 附带双维度导引说明：
  > “当前对象的张力为 TENSION={T}（代表言行激烈与直接程度），情绪效价为 VALENCE={E}（代表正负情绪倾向：负面表示烦躁/低落/委屈，正面表示愉快/安心/亲密，0为平和中立）。  
  > 请结合两者的象限组合组织当下的语言风格与语气：  
  > - E+ T+：友好 / 暧昧的直接表现；  
  > - E- T+：发泄 / 惩罚性质的直接表现；  
  > - E+ T-：友好 / 暧昧的柔和表现；  
  > - E- T-：吐槽 / 抱怨性质的柔和表现。  
  > 动作描写仍严格遵守情景模式、特殊空闲时段与 EFFECTIVE_STAGE 的边界，不得违规越界。”

## 5. 数据持久化、同步与调试

### 5.1 存档结构（`interaction`）
在每个角色的持久化交互字典（`interaction` 存档）中追加以下字段：
- `valence`: float，当前情绪效价，默认 `0.0`，范围 `[-100.0, 100.0]`。
- `valence_decay_at`: int，上次效价衰减结算的毫秒时间戳（可与张力 `decay_at` 共享时钟，或独立保存游标）。
- `valence_cooldowns`: dict，形如 `{"gratitude": 1731850000000}`。

### 5.2 设备同步（Devsync）
- 随现有的 `interaction:<pid>` 数据同步包一并同步。
- 遵循焦点设备操作最新原则，清空聊天记录时同步重置 `valence=0.0` 及对应冷却。

### 5.3 调试与隐藏显示
- 扩展现有的联网冷静期口令（原 `325799` 显示 Tension）：
  - 开启后，沟通页状态栏同时显示当前对象的双维度状态：`T: {T} | E: {E}`（保留最多两位小数，省略末尾 0）。
