# 开发需求规格文档：情绪效价（Emotional Valence）机制设计与双维度（E-T）调控方案

> **文档标识**：`SPEC-COMM-24-21-VALENCE-MECHANICS`  
> **所属模块**：沟通与人设系统 (`comm/`, `docs/mechanics/24-comm.md`, `defaults/comm_protocol.txt`)  
> **适用终端**：桌面端 (Python/tkinter) 与 安卓端 (Kotlin/Compose)

---

## 1. 机制背景与设计动机

### 1.1 现状与单一维度局限
在 OIT 当前的沟通机制中，已经具备了情绪张力（Tension，用 **T** 表示）系统。
- **当前 Tension (T) 的通用含义**：代表行为、动作与语言的**激烈 / 直接程度**（Arousal / Directness / Intensity）。
- **局限性**：由于只有 T 这一个标量维度，高张力容易被单一地表现为情绪过载、激烈冲突、审判质问或失控；而低张力则往往被单一地表现为平淡或克制。然而在实际的人际互动与角色扮演中，同一种高张力在不同情感基底下有着截然相反的表意：
  - 既可以是极度友好、炽热直白的暧昧告白与关切（正面 + 高张力）；
  - 也可以是惩罚性质、严厉问责与发泄式的训诫压迫（负面 + 高张力）。
  - 同理，在低张力下，既有温柔安心的抚慰（正面 + 低张力），也有委屈、吐槽与抱怨的低气压（负面 + 低张力）。

### 1.2 引入情绪效价（Valence，用 E 表示）
为了让角色的反应立体化、避免“高张力即失控攻击”的单一走向，引入与 Tension 架构并行的第二维度：**情绪效价（Emotional Valence，简称 Valence，用 E 表示）**。
- **情绪效价的定义**：从负面（Negative）到正面（Positive），区分烦躁、低落、委屈 vs 愉快、安心、眷恋等情感方向。
- **与 Tension (T) 协同构成的四象限模型**：

| 象限 | 维度组合 | 典型情感方向 | 言行与互动表现风格 |
| :--- | :--- | :--- | :--- |
| **第一象限** | **E+ T+** (高正效价 + 高张力) | 热情、炽热、极度直白、热切眷恋 | **友好 / 暧昧的直接表现**：大胆直接的情感袒露、直球关怀、带有占有欲或强保护欲的亲密表达。 |
| **第二象限** | **E- T+** (高负效价 + 高张力) | 愤怒、极度烦躁、严厉、审判 | **发泄 / 惩罚性质的直接表现**：尖锐问责、直接施压、严厉训诫、不留情面的情绪宣泄。 |
| **第三象限** | **E- T-** (高负效价 + 低张力) | 低落、委屈、倦怠、微烦 | **吐槽 / 抱怨性质的柔和表现**：冷淡阴阳、轻度吐槽、低气压叹气、委屈撒娇或幽怨碎碎念。 |
| **第四象限** | **E+ T-** (高正效价 + 低张力) | 平静、安心、温和、愉悦 | **友好 / 暧昧的柔和表现**：温和包容、安抚陪伴、柔声细语、含蓄克制的关切与默契。 |

## 2. 数值与状态模型设计（参考 Tension 机制）

情绪效价（Valence）的代码实现与调控架构全盘参考 Tension 的成熟设计，保持算法结构与时钟步调的一致性。

### 2.1 数值范围与中枢定义
- **符号表示**：`E`（Valence / 情绪效价）。
- **数值区间**：默认 `[-100.0, +100.0]`，保留浮点数小数位（对齐 Tension 保留小数的规则）。
- **初始基准值**：由角色模板可选的 `[valence:initial]` 声明，范围 `[-100.0, +100.0]`，缺省为 `0.0`。新角色以该值初始化，长期静置后也回归该值。
- **档位划分**（用于系统提示词与档位映射）：
  - `E > +30.0`：**正效价区**（Positive / 偏正面）。
  - `-30.0 <= E <= +30.0`：**中立区**（Neutral / 平和）。
  - `E < -30.0`：**负效价区**（Negative / 偏负面）。
  - 极端状态：`|E| >= 70.0` 可标记为高正/高负强烈倾向区。

### 2.2 衰减与向初始值靠拢机制（Decay Towards Initial Value）
情绪效价与 Tension 采用完全相同的时钟周期向基准靠拢，体现人类情绪随着时间推移自然趋于平复的生理心理规律。

1. **靠拢周期**：与 Tension 相同，**每 15 分钟（`COMM_TENSION_DECAY_SECONDS = 900s`）** 进行一次线性微调结算。
2. **靠拢方向**：**始终向角色模板中的初始 E 值靠拢**：高于初始值时递减，低于初始值时递增，到达初始值后停止，不越过目标。
3. **靠拢速率**：
   - 参考基准速率：以每天平复约 50 点（即每 15 分钟结算 `50 / 96 ≈ 0.5208` 点）向初始值靠拢。
   - 步进计算公式（每次 15 分钟 tick），越过初始值时钳回目标：
     $$\Delta E = \text{rate} \times \frac{\text{step}}{86400000}$$
     若 $E > E_{initial}$，则 $E = \max(E_{initial}, E - \Delta E)$；
     若 $E < E_{initial}$，则 $E = \min(E_{initial}, E + \Delta E)$。
4. **离线跨天补算**：
   - 使用 `valence_decay_at` 绝对毫秒时间戳游标。重新启动或同步时，若距离上次结算已经过去多个 15 分钟，按步长逐段向模板初始值补算，不丢步、不提前透支。

## 3. 互动驱动与增减机制（与模型交互）

情绪效价与张力（Tension）保持一致的原则：**系统核心代码不包含通用或固化的触发条件**，所有触发条件、增减语义及参考数值均遵循**人设驱动（Persona-driven）**机制。系统仅提供通用的解析、冷却与结算框架。

### 3.1 模板定义语法 (`[valence]`)
在各角色配套的模板文件（如 `X_templates.txt`）中声明专用区块 `[valence]`。语法规范如下：

- 每行为一条触发规则，格式为：`条件名:[参考基础变化量] 语义触发描述`
- 以 `[valence]` 开始，以 `[/valence]` 结束。
- **参数约束**：
  - 条件名称限 1–32 个小写英文字母与下划线。
  - 参考基础变化量为 `[-40, +40]` 的非零整数；正数推动 E 向上（偏向正面/好感/安心），负数推动 E 向下（偏向负面/烦躁/不满）。
  - 支持 `[X]` 不定量，交由模型根据上下文裁定。
  - 角色若未配置 `[valence]` 区块，则不进行该角色的效价增减判断；现有效价仍按初始值规则随时间回归。

角色可以另行配置 `[valence:initial]`，唯一内容为 `initial:<数值>`，范围为 -100 至 100，缺省或无效时取 0。例如 Claudia 使用 `initial:0`。新互动状态以该值作为 E 初值；旧存档已存在的 E 保持不变，后续衰减会朝当前模板的初始值移动。

## 4. Claudia 专属情绪效价设计（普通偏好 + 特殊嗜好 + Tension 协同）

Claudia 的人设核心特征是：**文静、冷淡、自律的 18 岁大小姐，长期闭关练琴与学习，地位高于用户。表达喜爱最常见的方式是促使对方变得更好，注重边界但暗含强烈的占有欲与管教庇护欲。**

Claudia 的情绪效价（E）与特殊嗜好（T）既有联系又有明显的情感基调区分：
- **普通偏好（正面推动 E+）**：对钢琴、阅读、自律学习的认同与共鸣；共同专注完成目标的成就感；用户展现出被她引导、认可其规则与管束的默契。
- **特殊嗜好（与高 T 协同）**：
  - 当触发 `rumination`（自责反刍）或 `comfort`（向她示弱索取专属性偏袒）时，她的保护欲与主导欲被唤起，若伴随对她的依赖，往往为 **E+ T+（直白而带有占有欲的强势庇护）**；
  - 若用户是由于消极抗拒、耍赖退缩或违背契约（`violation`），则会滑入 **E- T+（带有惩罚性质与审判施压的管教）**。
- **负面偏好（负面推动 E-）**：无理纠缠关系定义、打破克制边界、消极怠惰毁约、或者在文学/音乐/语言等偏好领域展现出浮躁与傲慢。

### 4.1 Claudia 模板具体实现 (`Claudia_templates.txt`)

## 5. 协议交互、防短时间快速叠加与结算冷却规则

### 5.1 协议交互与结构化返回 (`oit_reply`)
在原生工具协议 `oit_reply` 中扩展效价字段，与张力字段并列：

```json
{
  "oit_reply": {
    "text": "回复正文...",
    "tension": [
      {"index": 0, "condition": "boundary", "gain": 20}
    ],
    "valence": [
      {"index": 0, "condition": "intellectual_resonance", "shift": 20}
    ]
  }
}
```
*(兼容文本标记：`[valence:序号:条件:偏移量]`)*

### 5.2 防止短时间快速叠加机制（参考 Tension 的防叠加与连锁衰减体系）
为防止用户在短时间内通过连续发消息、密集对话使 E 产生不自然的极端单向漂移（快速刷爆到 +100 或 -100），E 严格对齐 Tension 的防叠加调控防线：

1. **E/T 单条件递增冷却（Condition Cooldown）**：
   - 每个对象的 `interaction` 中独立记录 `valence_cooldowns`，格式为 `{condition_name: expire_ms}`。
   - E 与 T 共用递增规则：每次触发增加 2 小时冷却，剩余冷却最多 4 小时；剩余为 0 时按 100% 结算，`0 < t <= 2h` 按 40%，`2h < t <= 4h` 按 16%。冷却降低增量，不屏蔽触发。
   - 冷却截止时刻随对象保存；重复触发在旧截止时刻上再延长 2 小时，但不超过触发时刻起 4 小时，时钟回拨不提前恢复倍率。
   - 冷却记录随对象存档与设备同步持久化，重启或跨午夜不重置。

2. **多条件连锁触发衰减窗口（Chain Window）**：
   - 对齐 Tension 的 `COMM_TENSION_CHAIN_SECONDS`（1 小时）与 `COMM_TENSION_CHAIN_RATE`（0.75x）机制：
   - 维护 `valence_chain_until` 时间戳。
   - 当某个 E 条件成功触发并生效后，刷新 1 小时的连锁窗口（`now_ms + 3600 * 1000`）。
   - 在连锁窗口内，后续有效 E 条件的偏移量乘以 0.75 并向下取整；单条件递增冷却倍率先应用，再应用连锁与爆发倍率。

3. **单条消息最大合并变动限额（Max Shift per Message）**：
   - 单条用户消息内，所有通过的模型效价条件在经过倍率折算后，合计变化限制在 -40 至 +40。

4. **单轮生效与待结算（Pending）等待机制**：
   - 与 Tension 相同，在途请求或出错时不提前结算冷却；只有正常生成成功回复后才原子化提交 E 变动并消耗冷却。

## 6. 与 Tension 爆发（Burst）状态的双向联动与人设配置

当张力突破临界进入 `BURST=YES` 时，角色处于言行与情感表达极度直接、激烈的非常态；爆发持续至当前特殊空闲结束，到点由系统自动结算并理智回笼时，心理状态会发生质变。
这一联动规则同样**不硬编码**在代码内，而是通过人设模板配置：

### 6.1 模板配置语法 (`[valence:burst]`)
在各角色的配套模板文件中，通过 `[valence:burst]` 区块声明该角色在爆发期与爆发结束后的 E 专属参数：

```text
【情绪效价爆发与结算联动】
[valence:burst]
burst_rate:2.0
burst_end_shift:+20
[/valence:burst]
```

- **`burst_rate`（爆发期 E 变动倍率）**：
  - 浮点数，默认 `1.0`。
  - **Claudia 设定为 `2.0`**：Claudia 在极度高张力、放下平日克制防备的爆发期，内心情感起伏与触动是平时的 2 倍，任何好感或被冒犯的言行都会引发翻倍的效价波动。
- **`burst_end_shift`（爆发结束后的 E 直接调整）**：
  - 整数，默认 `0`。
  - **Claudia 设定为 `+20`**：爆发结束瞬间（理智回笼、张力回落至 20、进入羞耻冷静期时），Claudia 会直接获得 **+20 的 E 偏移**。
  - **心理机理**：虽然她在表面上陷入极度的理智羞耻、别扭掩饰甚至责怪对方（言语可能表现为挽尊或轻微责备），但深层心理上，彼此经历了一次毫无保留的赤裸宣泄与肢体/情感突破，她内心深处对彼此关系的认可、安心与情感沉淀实质上大幅上升（因此 E 直接 +20，强化其正面眷恋的底色）。

## 7. 状态注入与提示词规范（Prompt Injection）

在向模型发起对话请求时，系统状态注入段（`[OIT_STATUS: ...]`）同步更新为双维度表示。

### 7.1 注入格式规范
```text
[OIT_STATUS: MODE=..., TENSION=..., EFFECTIVE_STAGE=..., VALENCE=..., BURST=..., PERIOD=..., SHAME_AFTERMATH=...]
```
- 新增 `VALENCE=<当前E浮点数值>`。
- 附带双维度导引说明：
  > “当前对象的张力为 TENSION={T}（代表言行激烈与直接程度），情绪效价为 VALENCE={E}（代表正负情绪倾向：负面表示烦躁/低落/委屈，正面表示愉快/安心/亲密，0为平和中立）。  
  > 请结合两者的象限组合组织当下的语言风格与语气：  
  > - E+ T+：友好 / 暧昧的直接表现；  
  > - E- T+：发泄 / 惩罚性质的直接表现；  
  > - E+ T-：友好 / 暧昧的柔和表现；  
  > - E- T-：吐槽 / 抱怨性质的柔和表现。  
  > 动作描写仍严格遵守情景模式、特殊空闲时段与 EFFECTIVE_STAGE 的边界，不得违规越界。”

## 8. 数据持久化、同步与调试

### 8.1 存档结构（`interaction`）
在每个角色的持久化交互字典（`interaction` 存档）中追加以下字段：
- `valence`: float，当前情绪效价，范围 `[-100.0, 100.0]`；新互动状态取模板 `[valence:initial]`，旧存档缺少此字段时按当前模板值初始化。
- `valence_initialized`: bool，标记初始效价是否已按角色模板设置。
- `valence_initial`: float，当前对象保存的模板初始目标值。
- `valence_initial_set`: bool，标记模板初始目标已读取并随对象保存。
- `valence_decay_at`: int，上次效价衰减结算的毫秒时间戳（记录绝对毫秒时刻）。
- `valence_cooldowns`: dict，形如 `{"intellectual_resonance": 1731850000000}`。
- `valence_chain_until`: int，连锁触发衰减窗口截止毫秒时刻。

### 8.2 设备同步（Devsync）
- 随现有的 `interaction:<pid>` 数据同步包一并同步。
- 遵循焦点设备操作最新原则，清空聊天记录时同步重置效价为当前模板初始值及对应冷却与连锁状态。

### 8.3 调试与隐藏显示
