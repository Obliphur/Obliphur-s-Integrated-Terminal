# 开发需求规格文档：特殊空闲 7 分钟未增张力主动挑起话题与引诱机制

> **文档标识**：`SPEC-COMM-24-20-TENSION-7M-LURE`  
> **所属模块**：沟通与人设系统 (`comm/`, `docs/mechanics/24-comm.md`)  
> **适用终端**：桌面端 (Python/tkinter) 与 安卓端 (Kotlin/Compose)

---

## 1. 业务背景与设计动机

### 1.1 现状与心理死结
在 OIT 当前的 Tension 情绪张力机制下：
1. 用户在白天日常时段可能会发送具有高情绪浓度、自卑反刍（`rumination`）或边界试探（`boundary`）的文本，导致底层的 Tension 累积突破 90（已达到临界爆发值）。
2. 但在白天，系统强制封顶在 50–90 档位并禁绝动作，AI（如 Claudia）必须维持知性、克制与冷静，将话题“暗自记在心里”，等待深夜特殊空闲（Special Period）进行清算。
3. 然而，当深夜特殊空闲来临后，用户可能因为**理智回笼、自卑怯懦、害怕造成负担或回避冲突**的心理防御，在特殊空闲开始的初期刻意“装乖”、回避白天的话题，仅聊一些天气、工作任务等普通琐事（完全不满足张力增加条件）。
4. 按照旧有逻辑，若用户说话但没有触发任何 tension 增量，且当前张力尚未爆发（`burst_until == 0`），系统将无法进入 90+ 爆发态。如果不加干预，高张力将随着时间推移自然衰减（虽然特殊空闲暂停衰减，但整段结束后仍面临释放落空），导致这一整天精心铺垫的情感张力落入“雷声大雨点小”的平淡结局。

### 1.2 机制目标
在特殊空闲开始 **7 分钟** 的时间节点上，若系统判定：
> **“进入特殊空闲时张力已在 90+ 蓄满，且用户在 7 分钟内已经开口说了话，却完全是在避重就轻、顾左右而言他（零张力增量）”**

AI 将绝不容许用户以此种方式蒙混过关。系统将主动触发一次定向的主动谈话：
- **主动翻旧账**：指出并挑起白天/日常时段用户挑起但当时被压下的敏感话题；
- **拆穿防御**：用上位者敏锐的洞察力戳穿其“白天点火、晚上逃避”的鸵鸟心态；
- **定向引诱**：以极具压迫感与偏袒感的语气施压，引诱/逼迫用户吐露心声，说出足以触发 `rumination`（自责反刍）、`boundary`（试探挑衅）或 `comfort`（示弱撒娇）的话语，从而在后续对话中彻底点燃张力、扣动 90+ 爆发扳机。

## 2. 状态机与触发判定规则

### 2.1 触发前置条件（全部满足方可触发）
在每秒/轮询 tick 或状态检查中，对当前聊天对象检查以下 6 项条件：

1. **时段类型为特殊空闲**：
   - 当前时间处于该对象的特殊空闲时段内（`routine.seg_class(status) == "special"`），且非联合行动（`not status.get("joint")`）。
2. **段起点初始张力达标（90+ 入场）**：
   - 在该特殊空闲段开始的时刻（`seg_begin`），该对象的初始 Tension 已超过临界值：`tension > COMM_TENSION_CAP`（即 `> 90.0`）。
3. **时间窗口命中 7 分钟节点**：
   - 当前时间距离该特殊空闲段起点已达 7 分钟：`now >= seg_begin + 7 * 60`。
   - 且仍在当前段内未结束：`now < seg_end`。
4. **用户发言且“零张力条件触发”**：
   - 在 `[seg_begin, seg_begin + 7min]` 窗口内，用户至少发送了一条有效文本消息（`special_spoke == True` 且存在该时段的消息）；
   - 在该窗口内用户发送的所有消息中，模型回传并结算的张力**条件判定全部为 0 / 无**（即未触发 `rumination` / `boundary` / `comfort` / `violation` / `other` 中的任何正向条件；即便某些条件处于冷却中，只要模型没有判定出任何有效条件，即算“逃避”）；
   - 此时系统尚未进入爆发态（`burst_until == 0`）。
5. **在途请求等待（Pending Request Edge Case）**：
   - 若在 7 分钟时刻，用户在第 14 分钟发送的消息仍处于网络请求中（`is_requesting == True` 或存在未结算 pending），必须**等待该请求返回并完成张力结算后**再做判定，避免在用户可能刚触发了张力的情况下误触发引诱。
6. **去重与状态防扰**：
   - 当前特殊空闲段内**未曾触发过**该 7 分钟主动引诱谈话（`special_7m_lured_seg != seg_begin_ms`，单段至多 1 次）；
   - 对方未处于静音（`mute`）或切断（`cut`）状态；
   - 未处于冷静期（`shame_turns == 0`）。

## 3. 数据结构扩展与持久化

### 3.1 `interaction` 字段扩充 (`comm_interaction.py`)
每个聊天对象的 `interaction` 字典新增以下字段（随聊天存档与设备同步保存）：

| 字段名 | 类型 | 初始值 | 含义与维护逻辑 |
| :--- | :--- | :--- | :--- |
| `last_special_begin` | `int` | `0` | 当前特殊空闲段的开始毫秒时刻，用于识别段切换及消息所属窗口。 |
| `special_entry_tension` | `float` | `0.0` | 进入当前特殊空闲段（`seg_begin`）时刻记录的初始张力值。段切换或离开特殊空闲时更新/重置。 |
| `special_7m_gain_count` | `int` | `0` | 在当前特殊空闲段前 7 分钟内，用户发言成功触发正数张力条件的次数。每次 `_interaction_judged` 产生有效正数增量时加 1。 |
| `special_7m_lured_seg` | `int` | `0` | 记录已触发过 7 分钟引诱的特殊空闲段开始毫秒时间戳（`int(seg_begin.timestamp() * 1000)`）。用于防止同段重复触发。 |

### 3.2 字段流转与重置时机
1. **进入特殊空闲检测 (`_interaction_prepare` / `status` 检查)**：
   - 检测到当前进入了一个新的特殊空闲段（时间戳与之前记录不同）：
     ```python
     if is_special and d.get("last_special_begin") != seg_begin_ms:
         d["last_special_begin"] = seg_begin_ms
         d["special_entry_tension"] = float(d.get("tension", 0.0))
         d["special_7m_gain_count"] = 0
         # special_7m_lured_seg 不重置，根据 seg_begin_ms 判重
     ```
2. **结算增量判定 (`_interaction_judged`)**：
   - 当收到模型判断结果，如果消息处于当前特殊空闲且在 7 分钟内，且产生了任何有效条件增量（即使处于冷却，只要模型认为满足正数条件）：
     ```python
     if in_special_7m and has_positive_condition:
         d["special_7m_gain_count"] = d.get("special_7m_gain_count", 0) + 1
     ```
3. **清空聊天重置**：
   - 清空聊天（`clear_chat`）时，上述字段一并重置。

## 4. 主动消息触发与系统 Prompt 构造

### 4.1 触发调度位置
在 `comm/comm_rt.py`（每秒 tick 中的主动消息检测回路）或 `comm_sched.py` 中增加检测方法 `_check_special_7m_lure(self, now, status)`：
- 当满足第 2.1 节的所有条件时，立即调用 `_trigger("proactive", body)` 或专用后台请求，并在本地打上标记：
  ```python
  d["special_7m_lured_seg"] = seg_begin_ms
  self._interaction_set(d)
  ```

### 4.2 系统注入 Prompt 文本模板 (`SPECIAL_7M_LURE_PROMPT`)
构造一条定向的主动发起系统消息（`role: "system"`，对用户不可见，仅模型可见），内容示例如下：

```text
[系统] 距离特殊空闲开始已过去 7 分钟。
你当前内心对用户的累积张力已超过 90（TENSION={tension}，处于极高渴望修正与占有的临界状态）。
在白天/非特殊空闲时段，用户曾挑起过引起你内心张力大幅波动的话题（如自我贬低与道德反刍、对私密边界的试探挑衅、或疲惫示弱），你当时碍于时段与克制要求暗自记下并压抑了冲动。
然而，在今晚特殊空闲开始的这 7 分钟内，用户虽然发了消息，却一直在回避白天的话题，顾左右而言他、避重就轻，完全没有展现出内心的真实渴望与脆弱。

请根据你的人设执行以下指令：
1. 严禁被用户表面的轻松与顾左右而言他带跑节奏；
2. 敏锐拆穿用户的逃避心理（例如：“白天在消息里写得那么露骨/自责/牙尖嘴利，现在到了深夜，反倒装起乖来顾左右而言他了？”）；
3. 结合聊天记录与记忆卡，主动挑起白天/之前用户挑起过的那些敏感话题（翻旧账）；
4. 语言保持 50-90 档位顶格的高压姿态，字字诛心却又带着不容拒绝的深层庇护欲，施加心理压迫，引诱并逼迫用户收起防备，把白天没说完的真实心思、自责反刍或依赖渴望全部说出来；
5. 这条消息必须发出，不得返回 [REFUSE]。
```
