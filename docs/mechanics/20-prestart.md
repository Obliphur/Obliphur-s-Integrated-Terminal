# 20. 提前启动 (仅 PC)

[← 返回目录](../../MECHANICS.md)

专注中可以先挑一两个程序"提前启动": 程序现在就跑起来, 但窗口藏起来、静音, 专注结束时再放出来.

- **按钮**: 专注中 (计时器在专注) Timer 页多出一个 "⏩ 提前启动". 点开先扫一遍程序
  (开始菜单快捷方式 + App Paths 注册表 + 正在运行的程序; 复用 AI 建议那边的扫描, 和窗口 / 进程枚举), 列成清单, 上面有搜索框.
- 清单只留**正常的程序**: 安装器 / 卸载器 (setup, uninstall, unins000 …), 更新器, 系统工具 / 驱动 / 配置项
  (控制面板, 注册表, 服务, 系统配置 …), 运行时和辅助进程 (python, node, ssh 代理 …) 都过滤掉;
  不能启动、又没在跑的也不列 (选了也没用).
- 清单里没有的程序: 点搜索框右边的 **"📂 打开文件管理器"**, 从资源管理器里挑 `.exe` / `.lnk`
  (同样要过上面的过滤, 安装器之类会被拒绝并提示); 挑中的**只加进清单**, 不会自动选中.
- 清单里每一行: **点一下只是选中 / 取消选中**(最多两个; 已经选了两个再点第三个, 会放开最早选的那个),
  点它右边的 **✕** 把这个程序从清单里去掉. 点**确定**才开始.
- **清单的添加 / 删除会保留**: ✕ 去掉的程序和文件管理器里加的程序存在 `prestart_list.json` (随数据文件夹加密, 重置时清掉),
  以后每次扫描完再套上: 去掉的不再出现, 加的一直在 (文件没了又没在运行的暂不显示); 同一个程序再次添加会取消"去掉".
  清单被删空时点"提前启动"仍然能打开窗口, 用文件管理器再加.
- **最多选 2 个**. 点"确定"以后:
  - 没在运行的程序用快捷方式 / 完整路径启动它; 已经在运行的不重复启动, 直接接管;
  - 先进入 **3 分钟的操作空窗期** (`GRACE_SECONDS`, 在 prestart.py 里): 程序照常显示、不静音, 方便先登录 / 更新;
    这期间 Timer 页的按钮变成 **"⏹ 提前终止"**.
- 点"提前终止"(或者 3 分钟自己到了) 才开始: 把它们的窗口**藏起来** (最小化的不碰),
  声音**静音** (只静音这些程序自己的音频会话, 不动系统音量和别的程序); 这之后按钮就藏起来, 不能再改.
- 每秒钟看一次: 这些程序 (以及它们派生出来的**子进程** —— 启动器 → 游戏这种) 新出现的窗口一样藏起来, 新出现的音频会话一样静音.
- **标记**: 选中的程序和它们的子进程在整个专注期间都被标记 (只增不减, 程序中途退出也保留), 效果等同于加入应用白名单; 联网白名单只在**专注期间**有效 (休息中 / 结束后照常判定).
- **空窗期里新启动的程序不受名单管**: 操作空窗期里**开始时没在运行**的程序 (比如 HMCL → javaw.exe) 不受应用名单 (不关窗口) 和网站 / 应用联网名单、代理-全屏蔽限制;
  原来就开着的程序照旧受名单管, 联网也不放行. 合约的网络禁令 (18.3) 照样拦. 空窗期结束后名单恢复, 只有被标记的程序继续放行.
  (标记按 exe 名认, 开始时就有同名程序在跑的新进程不标记, 免得连原来那个一起放行.)
- **应用白名单里的程序不动**: Rules 页应用白名单里的程序不会被标记、藏窗口或静音 (本来就放行); 专门在清单里选中提前启动的除外.
- **黑名单模式**: 空窗期里新启动的程序一律不标记 (没被禁的本来就放行, 不用藏), 黑名单里的程序也不享受空窗期放行 —— 禁令不能借提前启动绕过;
  只有专门在清单里选中的 (和它们的子进程) 才标记 / 放行 / 藏窗口.
- **空窗期里新启动的程序也标记**: 操作空窗期内新启动的进程 (开始时不在运行的; **不要求有窗口**, 所以 java.exe 这类无窗口的衍生进程也算;
  不含 OIT 自己、系统 / 命令行外壳 / 辅助进程, 名单见 prestart.py 的 `_NOISE_EXES`) 连同子进程一起被标记, 整个专注期间都在应用 / 网络白名单里.
  空窗期结束 (或提前终止) 后, 专注还没结束时, 被标记的程序**按 exe 名**再次试图开窗 (包括启动器退出后又被拉起的同名程序) 都会被重新藏起来并静音.
- **结束专注时全部放出来**: 藏起来的窗口显示出来 (不抢焦点), 取消静音; 程序照常运行.
  开始休息时 (结束专注 → 休息) 当场放出来, 不等每秒的检查; 所以休息期间看到的都是正常状态.
- 一次专注只能选一次. 从空闲开始的**新的一段专注**重新出现按钮, 重新选、重新有 3 分钟操作空窗期;
  **休息中直接开始专注** (按"开始专注" / 暂停休息后马上开始 / 别的设备在休息中开始专注) 时, 上一段专注的提前启动**原样接着**:
  不再重新选、不再给 3 分钟操作空窗期, 程序继续保持藏着 / 静音 (免得它们被应用名单当成普通程序关掉).
  这是为什么在休息里点"开始专注"不会把上一段提前启动的程序关掉.
  关闭 OIT 时也会把它们放出来.
- 每秒的检查 (tick) 本身出错也不会停: 出错只记日志, 下一秒照常继续 —— 提前启动藏起来的窗口不会因为一次异常就一直藏着.
- 提前启动不改变合约的判定: 程序本身还在运行, 只是窗口藏起来; 合约的网络禁令 (18.3) 照样拦它们.
- **窗口数不算它们的**: 提前启动的程序 (含子进程) 的窗口即使显示出来了, 也不算进 12 节的窗口数 ——
  系统上限的提醒和通道阻塞的判定都跳过它们, 防止误检测 (比如程序自己把窗口又弹了出来).
- **联网不拦 (只在专注期间)**: 专注中, 提前启动的程序 (含子进程) 联网时, Proxy 模式下不受 Rules 页的网站 / 应用名单限制 (4.1 的例外),
  代理-全屏蔽 (Proxy block-all, 包括合约的全频道阻塞干扰切换过去的) 也不拦; 开始休息 / 结束专注以后回到正常判定, 不再有无条件联网.
  例外: 合约的网络禁令 (18.3) 禁止联网的程序照样拦.
  (Adapter 禁用网卡时整台电脑都断网, 管不了单个程序.)

### 20.1 触发隐藏的窗口 (设置 → 窗口)

- 设置 → 窗口 里有一份**窗口标题关键字**列表 (一行一个, 不随设备同步, 保存在数据文件夹 `hidden_windows.json`, 重置时清掉).
- **标题里包含**其中任意一项 (不分大小写) 的窗口, 一出现就被藏起来, 它的程序也一直被当成"提前启动"的窗口处理:
  之后它再开的窗口同样藏起来, 应用名单不会关掉它, 静音, 窗口数上限 / 通道阻塞也不数它的窗口.
- 但它**不会**获得提前启动的联网豁免: 联网照常按网站 / 应用名单和代理-全屏蔽判定, 合约的网络禁令也照常生效.
- 自动藏起来的窗口在 OIT 运行期间一直保持隐藏 (休息中也是); 把标题从列表里去掉 (保存后) 或者关闭 OIT 时放出来.
  用文件管理器 / 应用名单仍然可以正常操作这个程序, 只是它一露头就会被重新藏起来.
- 和提前启动的区别只有一个: 提前启动是用户主动选的、专注期间可以无条件联网; 这一类只是"不关掉、藏起来", 没有联网特权.
