# 4. 网站 / 应用名单 (设置 → 联网 → 🛡 规则, 仅 Proxy 模式; 代理-全屏蔽 (Proxy block-all) 下只有应用名单)

[← 返回目录](../../MECHANICS.md)

规则不再是左侧导航里的一页: 在 设置 → 联网 的最上面有一栏"🛡 规则", 点"打开"弹出规则窗口 (电脑: 独立小窗; 手机: 全屏弹窗), 内容和以前的规则页一样.
过滤名单模式 (`FILTER_MODE`) 在这个窗口里切换, 设置页里不再重复列出. 下文的"Rules 页"指这个窗口.

### 4.1 两种名单模式

只有当前模式对应的两张名单起作用.

| 模式 | 离线时 | 联网会话中 |
| --- | --- | --- |
| **黑名单模式** (默认) | 只拦黑名单, 其余放行 | 全部放行 |
| **白名单模式** | 只放行网站白名单里的网站, 其余拦截 | 全部放行 |

白名单模式下两张名单分工不同: **网站白名单**决定能连哪些网站 (不管是哪个程序发起的连接);
**应用白名单**只决定专注 / 空闲时哪些程序的窗口可以开着 (4.7), 不会让程序绕过网站白名单.
例如把 `chrome.exe` 放进应用白名单, Chrome 的窗口不会被关掉, 但它仍然只能打开网站白名单里的网站;
anki 之类要同步的程序, 需要把它用的域名也加进网站白名单.

**AI 接口例外**: 当前服务商 Base URL 的主机 (预设服务商或自定义中转) 始终放行, 不受白名单 / 黑名单 / 代理-全屏蔽影响, 这样聊天和 AI 名单建议不会因为服务商域名不在名单里就连不上; 合约的网络禁令仍然优先 (18.3). 手机上 VPN 的 DNS 过滤同样例外放行这个主机; 全屏蔽 (Proxy block-all) 时也放行 OIT 自己的这条 HTTPS 连接 (其他应用的连接照样丢掉, 14.2).

开启沟通的 AI 语音后，各语音配置的 API 主机也加入上述例外，关闭后移除；仍受合约网络禁令约束（24.1）。

默认名单是空的, 所以 Proxy + 黑名单 + 空名单时, 实际上什么都不拦.

例外: **提前启动 (第 20 节) 的程序**不看这两张名单 —— 专注期间它们连什么网站都放行 (代理-全屏蔽也不拦);
开始休息 / 结束专注以后照常按名单判定.

你们贴心的作者已经考虑到了戒断反应和设置参数的资料查询需要,所以默认是放行的.
在完成初始设置后,各项设置的修改限制才会生效.
作者比较喜欢用proxy block-all.
对了,应用黑白名单只针对空闲与专注时段,休息时段全部放行,但是联网需要另外申请.

### 4.2 判定顺序

1. `localhost`, `127.*`, `::1`, `0.0.0.0` 一律放行. 系统代理也设置了绕过本机地址: `localhost;127.*;[::1]`.
2. 合约的网络禁令 (18.3) 禁止联网的程序和封锁的网站 → 拦截 (联网会话中 / 白名单 / 提前启动也一样).
3. 联网会话中 → 放行 (两种名单模式, 以及代理-全屏蔽 (Proxy block-all), 都一样). Claude Code 的连接 (`anthropic.com`, `claude.ai` 及其子域名) 同样放行, 始终不受名单 / 全屏蔽限制.
4. 提前启动 (第 20 节) 的程序 (含子进程) → 放行 (两种名单模式, 以及代理-全屏蔽, 都一样).
5. 代理-全屏蔽 (Proxy block-all): 其余一律拦截 (名单不参与联网判定).
6. 白名单模式: 域名在网站白名单 → 放行 (条目是 bilibili.com 并且有 UP 主白名单 → 浏览器开着的 B 站页面全是白名单 UP 主的才放行, 4.8); 其余拦截 (应用白名单不参与联网判定).
7. 黑名单模式: 应用在黑名单 → 拦截; 域名在黑名单 → 拦截 (条目是 bilibili.com 并且有 UP 主白名单 → 浏览器开着的 B 站页面全是白名单 UP 主的才例外放行, 4.8); 其余放行.

### 4.3 条目格式

- 网站: 写域名即可, 子域名自动包含. 写 `bilibili.com` 会同时匹配 `www.bilibili.com`, 但不会匹配 `notbilibili.com`.
  粘贴完整网址也可以, `https://www.a.com/x?y=1` 会被整理成 `www.a.com`, `*.a.com` 会被整理成 `a.com`.
  不含 `.` 的名字视为无效.
- 应用: 写 exe 文件名, 不区分大小写, 可以省略 `.exe`, 也可以粘贴完整路径. 例如 `Steam` → `steam.exe`.
- 应用识别方式: 代理根据连接查出发起它的进程, 再取 exe 名. 查到的结果缓存 30 秒.
- UP 主 (4.8): 粘贴 UP 主的主页链接 (`https://space.bilibili.com/2742391?spm_id_from=…`) 或 UID (`2742391`, `UID:2742391`), 整理成 `bilibili.com/2742391`.

### 4.4 修改名单的冷静期

黑名单与白名单规则相同, 不区分放宽还是收紧:

- 名单的**所有改动** (加入和删除, 包括 4.8 的 UP 主名单) 都要等 **48 小时**才生效, 新条目第一次加入也一样.
- 配置期内 (见 1.1) 所有改动立即生效, 排队中的改动也立即生效.
- 排队中的改动可以在"等待生效的改动"里取消.
  对排队中删除的条目再点一次加入, 或者对排队中加入的条目点删除, 也等于取消, 名单保持原样.
- 程序每 **5 秒**检查一次有没有到期的改动 (不用打开 Rules 页), 到期就交给过滤代理, 弹出提示, 并写入 `settings_changes.log`.
- **提前设置新模式的名单**: 过滤名单模式的切换在排队时 (设置 → 过滤名单模式, 也要等 48 小时), 新模式里 (当前模式没有的) 那两张名单现在还不起作用,
  这时对它们的改动**立即保存**, 不用再各等 48 小时 (它们要等模式切换生效才起作用, 切换本身已经在等了). 电脑: Rules 页在切换排队时多一个"✏ 提前设置…的名单"按钮, 点了页面显示 / 编辑新模式的名单 (AI 建议也针对它), 再点回到当前名单; 手机: 名单页上方本来就能切换看黑 / 白名单, 排队中的新模式那一边的改动立即保存.
  当前模式的名单照常等 48 小时; 切换被取消后, 提前设置的内容留在那一边 (下次切换过去仍要等 48 小时).


### 4.5 连接处理

- 支持 HTTP 代理和 HTTPS 隧道. HTTPS 内容不解密, 只看目标域名.
- 被拦截的请求返回 403, HTTP 页面直接显示拦截原因 (离线只放行网站白名单 / 全屏蔽 / 网站或应用在黑名单中).
- **HTTPS 拦截页 (电脑)**: 浏览器不会显示 CONNECT 失败时的 403 正文, 所以不能靠它直接展示提示页. 被拦截后 30 秒内,
  OIT 用 Windows UI Automation 查看前台浏览器当前标签页的地址; 地址域名和发起请求的浏览器都与拦截记录一致、按最新规则仍被拦截时,
  将当前标签页转到 `http://127.0.0.1:<代理端口>/oit-block/<随机标识>` 显示 OIT 拦截原因, 可点"重新访问"回到原网址.
  本机页面直接由过滤代理提供, 不连目标网站, 不解密 HTTPS, 不安装证书; URL 和提示只存在内存中, 最多保留 256 条, 停止代理即清除.
  后台请求的域名与当前地址不一致时不跳转; 用户正在编辑地址栏时也不改动. 跳转只向指定窗口提交地址, 不模拟全局按键或使用剪贴板.
  Chromium 地址栏省略 `www.` 时兼容这一显示差异; 根域名和 `www.` 的放行结果不同时不推断, 避免误跳转允许的页面.
  识别的浏览器同 4.8 (Chrome / Edge / Firefox 等); 后台标签页、无地址栏 / 全屏窗口或 UI Automation 不可用时, 仍执行网络拦截, 可能显示浏览器自身的连接错误.
- 已经建立的连接每 **1 秒**按当前规则重新判定一次. 联网会话结束后, 不该放行的连接会在约 1 秒内被切断.
- 每个请求单独一条连接. 连接建立超时 10 秒, 空闲 300 秒后断开, 同时最多 256 个连接.
- 如果原本系统里设置了别的 HTTP 代理 (例如其他代理软件), 放行的流量会转发给它, 而不是直连.
  退出 Proxy 模式或重置时, 原来的系统代理设置会被还原 (备份在 `sysproxy_backup.json`).

### 4.6 拦截记录

放行 / 拦截的计数和拦截记录属于统计, 见 **8.6**.

### 4.7 应用名单: 关掉前台窗口

只按连接认应用, 很多程序拦不住 (例如不走系统代理的程序). 所以 Proxy 断网方式下, 应用名单另外按**前台窗口**生效
(白名单模式下应用白名单**只**在这里起作用, 见 4.1):

- 每 **1 秒**看一次当前前台窗口属于哪个程序 (exe 名):
  - 黑名单模式: 程序在应用黑名单里 → 立即关掉这个窗口;
  - 白名单模式: 程序不在应用白名单里 → 立即关掉这个窗口.
  - 只在**专注 / 空闲**时这样做, **休息中全部放行**; 和是不是在联网会话中无关 (以前联网会话中白名单模式不管).
- 关闭方式和第 12 节一样是 WM_CLOSE (发给窗口的顶层窗口): 有未保存内容的程序会照常询问是否保存.
  前台是这个程序的对话框 (例如"是否保存") 时先不关, 等对话框关掉、主窗口回到前台再关.
- 永远不关: 桌面, 任务栏, 开始菜单, 文件资源管理器, 命令行窗口, 任务管理器, 设置, 锁屏 / 登录 / 权限确认等系统界面, OIT 自己 (包括单独运行的卸载程序), 以及查不到 exe 的窗口.
- 关掉时弹出提示 (同一个程序 5 秒内只提示一次), 并记进 `window_guard.log`.
- 在 Proxy 和 代理-全屏蔽 (Proxy block-all) 断网方式下生效 (全屏蔽时这是唯一起作用的名单, 3.2.1).

### 4.8 UP 主名单 (bilibili.com, 仅电脑)

代理只看得到域名, 看不到 HTTPS 的路径, 分不出一条连接属于哪位 UP 主. 所以 OIT 另外看浏览器此刻开着哪个页面 (地址栏里的网址).

- **入口**: Rules 页的网站名单里选中 `bilibili.com` (或它的子域名条目, 例如 `space.bilibili.com`), **再点一下**, 或点名单下的"UP 主…", 打开这个条目的 UP 主名单.
  有 UP 主名单的站点条目后面带 `▸ UP` (名单里有人时带数量). **UP 主名单只有白名单**, 黑名单模式和白名单模式共用同一张, 都是"只放行名单里的 UP 主的主页和视频":
  - 条目在**白名单**里: 名单里的 UP 主放行, 其余的 B 站页面拦截. 名单是空的就整站放行;
  - 条目在**黑名单**里: 整站拦截, 只有名单里的 UP 主的主页和视频例外放行. 名单是空的就整站拦 (和没有这个功能时一样).
  (旧版本有过 UP 主黑名单, 现在不读, 里面的 UP 主不会转成白名单.)
- **白名单里的 `bilibili.com` 连带放行它的图片 / 视频流 / 接口域名**: `bilivideo.com`, `bilivideo.cn`, `hdslb.com`, `biliapi.net`, `biliapi.com`, `acgvideo.com` (只写 bilibili.com 的话视频放不出来).
  有 UP 主白名单时, 这些域名同样要浏览器开着白名单 UP 主的页面才放行. 只写子域名 (如 `space.bilibili.com`) 不连带. 黑名单里的条目不连带, 照旧只管写出来的域名.
- **条目**: 见 4.3. 昵称在后台查 (哔哩哔哩的公开接口), 查到了显示在 UID 前面, 记在数据目录的 `up_names.json`; 查不到只显示 UID.
- **冷静期** (4.4): 加入和删除都要排队, 配置期内立即生效. 排队中的改动在"等待生效的改动"里显示和取消, UP 主名单里也带 ⏳. 和网站名单一样**不随设备同步** (15.2).
- **判定** (只在离线时; 联网会话中全部放行, 合约的网络禁令 (18.3) 照旧优先):
  1. 连接命中的网站条目是 bilibili.com 一类, 并且有 UP 主白名单时才去看浏览器. 没有 UP 主名单时一个窗口也不碰.
  2. "浏览器" = 发起这条连接的程序. 只看它的窗口里**标题带"哔哩哔哩"或"bilibili"**的, 以及此刻在最前面的窗口 (刚在地址栏输入网址按回车时标题还是旧页面),
     用 Windows UI Automation 读地址栏当前的网址, 每个窗口只看当前标签页; 地址不是哔哩哔哩的丢掉. 认得 Chrome, Edge, Brave, Vivaldi, Opera, Firefox 等. 地址只在内存里用, 不写文件.
  3. 每个页面属于哪些 UP 主: UP 主主页 (`space.bilibili.com/UID`, 包括下面的 `/video`, `/dynamic` 等) 属于这位 UP 主;
     视频 (`/video/BV…`, `/video/av…`) 属于投稿人, 合作投稿的每位都算. 投稿人通过哔哩哔哩公开接口查 (只发 BV / av 号), 查到的缓存 6 小时, 本机直接联网, 不经过自己的过滤代理.
     首页, 搜索, 直播间, 番剧, 专栏, 动态详情等**不属于任何 UP 主**. 读不到地址, 查不到投稿人的页面**认不出来**.
  4. 这个浏览器至少开着一个 B 站页面, 而且**每一个**都是白名单里某位 UP 主的主页或视频, 才放行它的 B 站连接 (白名单模式下是放行, 黑名单模式下是例外放行). 有一个窗口开着别的 B 站页面 (包括首页), 或者认不出来, 它的 B 站连接全部拦截 —— 代理分不清连接属于哪个窗口.
  5. 已经建立的连接每 1 秒重新判定 (4.5): 页面一离开白名单 UP 主, 约 1 秒内连接被切断.
- **只在有 B 站连接要判定时才读窗口**, 在单独的线程里读, 结果缓存 0.6 秒. 读不出来 (UI Automation 不可用, 不认识的浏览器) 就按严格的一侧办: 不放行.
- **局限**:
  - 只认浏览器. 哔哩哔哩客户端等其他程序的连接没有"页面": 有 UP 主白名单时一律拦截.
  - 在页面里点链接跳到另一个页面时, 浏览器在换页之前就发出了第一批连接, 这时地址栏还是旧页面, 这一批可能按旧页面判定 (放行的变拦, 拦的变放行), 刷新一次就行;
    从地址栏输入 / 粘贴的网址不受影响.
  - 后台标签页的地址读不到.
  - 读地址栏会让浏览器打开辅助功能支持 (Chrome / Edge 的页面渲染可能略慢一点); 只有名单里有 UP 主并且有 B 站连接要判定时才会读.
  - 手机上没有对应, 见 14.2.

### 4.9 加入白名单时探测它引发的其他网站 (仅电脑)

只写 `zhihu.com` 的话页面是打不开全的: 图片在 `zhimg.com`, 验证码在 `dun.163.com` ……白名单模式下这些要一个一个加. 所以**加入网站白名单时, 电脑会真的去连这个网站, 把它引发的其他网站一起加入名单**.

- **什么时候**: Rules 页的网站白名单里"添加"或"从本机选择…"加入了新网站 (加入成功, 不管是排队还是立即生效). AI 建议, UP 主名单, 黑名单不触发. 多个网站一个一个来, 后台进行, 每个十几秒 (最多 30 秒), 开始和结束时各弹一个提示.
- **怎么探测** (`netproxy/sitescan.py`): 起一个只记录的本地代理 (全部放行, 不碰系统代理), 用**无界面的浏览器** (Edge, 没有就 Chrome; 临时用户目录, 用完删掉) 通过它打开 `https://网站/`,
  网站加载完 (4 秒没有新的连接, 最长 30 秒) 就关掉浏览器, 代理看到的所有域名就是它引发的网站 —— 浏览器真的执行了页面的脚本, 所以脚本发出的请求 (接口, 统计, 验证码) 也在里面.
  转发走 OIT 自己的进程, 先看能不能直连这个网站, 连不上再经过原来的代理 (Clash 之类, 同 16 的下载路线), 不经过 OIT 自己的过滤代理, 所以离线时也能探测.
  浏览器围栏 (3.2.2) 只拦浏览器直连外网, 无界面浏览器只连本机的代理, 不受影响; 它没有窗口, 窗口守卫 (4.7) 碰不到它.
  找不到浏览器 / 浏览器没起来 / 连不上时退回"读网页": 下载首页和它的样式表, 取 script / img / iframe / link 等标签和 `url()` 里的域名 (看不到脚本运行之后才发出的请求).
- **挑哪些加入**: 去掉 IP 地址, 本机, 浏览器自己的后台连接 (更新, 钓鱼网站库, 新标签页, 账号 / 奖励, 证书吊销检查), 已经被主网站放行的 (子域名, `bilibili.com` 连带的 `hdslb.com` 等, 4.8),
  名单里已有条目放行的; 其余按出现的先后, 最多 80 个. 域名按原样加 (`pic1.zhimg.com` 就是 `pic1.zhimg.com`, 不会扩大成 `zhimg.com`).
- **冷静期**: 引发的网站和主网站是同一批改动, **同一个生效时间** (4.4: 排队 48 小时, 配置期立即生效). 探测期间主网站就已经在排队了; 探测失败 (连不上) 只有主网站本身.
- **显示**: 引发的网站**归在主网站名下**, 默认收起: 主网站前面是 ▶ , 后面带 `+N` (引发了 N 个); **点一下主网站**展开 (▼), 引发的网站缩进列在下面, 再点一下收起.
  (`bilibili.com` 这样有 UP 主名单的主网站, 展开后 "UP 主…" 按钮照常用, 只是"再点一下选中的条目打开 UP 主名单"让给了展开.)
  "等待生效的改动"里引发的网站折进主网站那一行 (`(+N)`), 取消那一行时一起取消.
- **删除**: 删主网站 = 删它名下**只属于它**的引发的网站 (同样排队, 同一个生效时间; 排队中的加入就是一起取消); 别的主网站名下也有的不删. 选中展开后的某一个引发的网站再删 = 只删它.
  自己再手动添加一个引发的网站 = 它从此是单独的一条, 不再属于主网站 (删主网站不会带走它).
  第二个主网站引发了已经在名单里 (别的主网站名下) 的网站时不重复加, 但也记在它名下, 这样删掉前一个主网站时不会把它带走.
- **判定**: 引发的网站就是网站白名单里普通的条目 (子域名自动包含, 4.2 的判定不变); 分组只管显示和连带删除. 存盘: `net_rules.json` 里的 `groups` (主网站 → 引发的网站).
- **局限**: 只看首页加载出来的 (不登录, 不点击): 登录后 / 点进去才发出的请求, 要自己再加; 视频网站放视频时才连的 CDN 也一样; 不同步给其他设备, 手机没有这个功能 (手机的网站名单见 14.2).
