# 15. 设备同步 (设置 → 基本设置, 两端都是 Proxy 断网方式时)

[← 返回目录](../../MECHANICS.md)

同一个局域网 (同一个 Wi-Fi / 路由器) 里的 OIT 可以互相绑定, Windows 和 Android 都可以. 不经过任何服务器.

### 15.1 绑定

1. 在一台设备的 设置 → 基本设置 → 🔗 设备同步, 按"🔍 寻找设备" (同一局域网里广播), 或者在地址栏填对方的 `IP` / `IP:端口` 后按"按地址连接".
2. 在找到的设备上选"绑定 · 本机为母端"或"绑定 · 对方为母端". 选对方为母端时要再确认一次.
3. 对方弹出"绑定请求", 写明配对码和谁是母端. 两边显示的 6 位**配对码**应该一样 (防止被局域网里的其他设备冒充); 在对方点"接受".
   2 分钟内没有确认就作废. 等待期间偶尔连不上 (Wi-Fi 丢包) 不算失败, 连续 5 次连不上才算.
4. 绑定完成后, **子端**马上用母端的数据初始化:
   - 设置, 整点记录, 计时器 (此刻的专注 / 休息, 积攒的休息时间, 本周连点领取记录), 全部换成母端的; 名单不动;
   - 子端自己的历史数据 (学习时长, 专注时间段, 联网理由, 窗口 / 应用使用时间) 清掉, 之后显示的是母端的;
   - 子端今天已经用掉的联网额度和借贷**保留** (绑定不能用来重置额度).
   初始化完成之前, 子端不参加普通同步; 母端这时发来的同步请求得到"正在初始化", 不算同步失败.
   发起方要等下一次查询 (每 1.5 秒) 才知道对方已接受, 被请求的一方是子端时, 初始化请求在这之前会被拒绝, 所以每 1.5 秒重试一次, 最多约 18 秒.
- 电脑要用 Proxy 或代理-全屏蔽 (Proxy block-all)才能绑定和同步 (Adapter 方式下网卡被禁用, 连不上局域网); 不是时请求会被拒绝, 已绑定的也暂停同步.
  手机上两种断网方式 (代理-全屏蔽 (Proxy block-all) / 代理 - 规则过滤) 都保留局域网, 都可以同步.
- **解除绑定**: 在"已绑定的设备"里选中后按"解除绑定" (确认一次).
  - **1.0.467 起无代价** (`devsync.UNBIND_FREE` / `SyncService.UNBIND_FREE` 为真): 确认后 5 秒内解除, **不清空任何数据**, 也没有冷静期; 确认框写"不会清空本机的数据". 开关关着时按下面的冷静期办.
  - **冷静期 120 小时** (开关关着时): 这台设备一行写着"将在 MM-DD HH:MM 解除绑定", 期间照常同步; 电脑上再按"解除绑定" (手机上按"✕ 取消解除绑定") 可以取消.
  - 到时间后解除, 并**重置操作解除的这一台** (同第 9 节: 数据删光, 重新打开, 重新开始配置期), **只清空本机的数据, 不影响对方的数据**: 不请其他设备清空 (对方也不清空),
    本机和其他设备的绑定照样留着 (它们的数据会再同步过来). 对方只是被通知"本机解除了和它的绑定", 删掉这条绑定和本机留在它那里的状态 (数据不动). 重开后提示"已解除和 X 的绑定, 本机的数据已经清空. X 的数据不受影响."
  - 到时间时对方离线: 本机照样解除并重置, 通知留着, 每 30 秒再送一次 (它的地址变了时按广播找到的地址送), 直到送到; 62 天后放弃.
  - 对方已经解除了和本机的绑定 (或重置过, 显示"对方已经解除了绑定") 时不用等, 直接解除, 本机也不清空什么.
  **重置** (第 9 节) 请所有绑定的设备一起清空数据, 绑定保留; **卸载** (9.1) 请它们清空数据并解除和本机的绑定.
- **绑定的设备列表里每台一行写同步状态** (1.0.238: 直接写状态, 不再写成"同步失败: 对方没有在等连接 ……"那样的一句话): `同步状态: <状态>  ·  上次成功 <时刻>`.
  状态: **正常** (最近一次同步成功) / **未同步** (还没同步过) / **拒绝连接** (对方主机开着, OIT 没在运行) / **超时** (对方没有响应: 没在运行, 或被系统暂停了) /
  **本机非 Proxy** / **对方非 Proxy** / **已被解除绑定** (对方解除了绑定或重置过, 在这里解除后重新绑定) / **等待清空** (本机重置过, 对方还没清空) / **对方在别的桌面** (away) / **出错: <原因>**.
  解除绑定在冷静期中时这一行写"将在 … 解除绑定". 绑定 / 连接时出的错 (弹出的提示) 仍写成句子.
- **没有先解除绑定就卸载了 OIT 的设备** (手机卸载时 OIT 来不及通知别人): 留下的设备上它一直显示"同步失败", 在"已绑定的设备"里解除绑定即可.
  解除绑定一律记进"已删除的设备" (同重置 / 卸载, 记住 62 天) 并转告其他设备: 之后别的设备 (或解除前已经发出的那一轮同步) 再送来它的旧状态 / 旧账都不收.
  以前只删掉绑定, 它的状态又被送回来, 之后一直显示"离线" (计时页的"有设备离线" 提醒也一直在), 却不在绑定列表里, 再也解除不掉.
- **有绑定的设备刚离线时** (15.3 的判定; 关机 / 断网不算), **焦点设备** (最后有人操作的那台, 同下面的整点提示音) 响一次提示音, 并提示"X 离线了". 刚打开 OIT 时已经离线的不响; 外出期间不响 (8.4).
- 没有绑定、只是别的设备转交过来的设备: 本机一台绑定的设备都没有时全部删掉 (不可能还有人转交); 否则 24 小时没有新消息就删掉.
  旧版本留下的这种残留, 升级后自动清掉.

### 15.2 同步什么

**母端每 20 秒**向每台子端发一次同步请求: 子端并入母端发来的内容, 再把合并后的结果回给母端, 两边一致.
子端不主动发请求, 只在第一次初始化和按"立即同步"时向母端发. 连不上时母端广播找一下 (对方的地址可能变了) 再试.
**哪台设备的操作最新, 就以哪台为准**: 每一项单独记最后修改的时间, 合并时取时间最新的那份.

| 类别 | 内容 | 规则 |
| --- | --- | --- |
| 设置 | 除下面几项以外的全部设置, 包括排队中的修改, 配置期, 借贷后的一次免等待 | 每一项单独比较, 后改的覆盖先改的 |
| | 不同步: 断网方式, 过滤名单模式, 界面字号, 整点提示音, 任务栏窗口数上限, 窗口 / 应用使用时间统计, 违规记录, 两项更新设置 | 每台设备自己决定 |
| 规则 | **不同步**: 网站 / 应用的黑白名单和排队中的改动都是每台设备自己的 | — |
| 整点记录 | 每一小时的内容 | 每一小时单独比较; 超时自动记录的内容 (`Sleeping`) 永远让位给自己填写的 |
| 计时器 | 此刻在专注 (从几点开始, "还在吗"确认过几次) / 休息 (到几点结束) / 空闲 / **睡眠** (从几点开始, 23 节); 积攒的休息时间 (以及其中还没折算的非手动结束留下的部分, 6.8); 本周连点领取了多少 | 后改的覆盖先改的: 在电脑上开始专注, 手机也进入同一段专注; 在手机上结束, 电脑也跟着进入休息; 在一台设备上睡眠, 另一台也盖上"起床"页, 任何一台起床两边都醒 |
| 联网额度 | 每台设备今天用掉的额度, 借到的额度, 明天要还的, 今天的欠款 | **合计**: 所有设备共用一份每日额度 |
| 统计 | 学习时长, 专注时间段, 联网理由, 窗口 / 应用使用时间 | 合计 (见 8.4) |
| 成就 | 达成了哪些, 什么时候达成的 (第 17 节) | 合并: 任何一台设备达成都算, 达成时刻取最早的; 达成了不会被同步取消 |
| 合约 | 进行中的合约 (词条, 降级, 违反次数, 合约中给出的休息时间, 黑雾 / 全频道阻塞干扰的计数); 结束了的合约 (第 18 节) | 进行中的: 后改的覆盖先改的; 结束了的: 合并. 还没开始的词条选择不同步 |
| 行为模式 | 每次外出的开始 / 结束时刻, 时长, 种类 (上学 / 工作 / 外出), 是否已经发过休息时间 (第 21 节); 自由学习的外出回来后第一次同步有优先权 (21.6) | 每一次单独比较, 后改的覆盖先改的; 休息时间只由开始外出的设备发一次, `mode_since` (整点记录从什么时候开始用这个模式) 每台设备各自记 |
| API 设置 | 默认配置; 最多 10 份命名配置 (名字 / 服务商预设 / 模型类型 / Base URL / 型号 / API Key); 每个 AI 用哪份配置 (文档 `ai`, 1.0.416 / 1.0.444) | 每一项单独比较, 后改的覆盖先改的; Key 在同步通道里封着传, 到对方设备后重新加密保存; 空值不覆盖已有的值 |
| 指令 | 领到的指令 (进行中的, 和最近 3 天已经完成 / 作废的), 奖励 (结算过没有), 今天的 n (第 22.8 节) | 每一项单独比较, 但**已经结束的永远盖过进行中的**; 各设备自己累计的进度 (专注 / 休息秒数, 统计页停留) 不同步 |
| 状态 | 每台设备此刻在专注 / 休息 / 联网, 最后一次有人操作的时间; 是否停在指令页上 | Timer 页卡片下方 (60 秒没有消息的显示"离线", 见 8.4), 设备同步的"已绑定的设备"里显示; 最后操作时间用来决定哪台设备出声 |

- "后改的覆盖先改的"按各设备的系统时间比较, 设备之间的时间差应在 5 分钟以内 (超过时同步请求会被拒绝).
- 联网额度合计的意思: 每台设备只计自己联网的时间, 但"今日剩余"= 今天额度 - 所有设备用掉的; 两台设备同时联网时两边都在消耗.
  紧急借贷"最多能借多少"和"借得太多时的提醒"也按所有设备的合计算.
- 每台设备的联网会话 (申请, 冷静期, 联网中) 各自独立: 在电脑上申请联网, 手机不会跟着联网.
- **计时器的记录只记一次**: 结束专注 / 暂停休息时, 由按按钮的那台设备记学习时长和这一段专注 / 休息; 照着切换的设备不重复记.
  没人按按钮的操作 (专注没回应"还在吗"自动结束, 休息自然走完时记下这一段) 由最后改动计时器状态的那台设备做;
  那台设备 2 分钟内没同步过时, 本机来做. "还在吗"提醒在每台设备上都会弹, 在任何一台上关掉都算确认.
- **提示音只在最后有人操作的设备上响** (键盘 / 鼠标 / 触屏, 比较 2 分钟内同步过的设备; 电脑上**别的程序里的键盘 / 鼠标也算**, 不只 OIT 窗口里的点击):
  整点提示音、绑定设备离线提示音、沟通收到新消息的提示音、休息只剩 1 分钟的提示音都遵守这一条;
  其他设备只在 Hour Log / 沟通页标出待填写 / 未读, 手机上的通知也不出声. 休息结束后"该开始下一轮了"的提醒同样只在这台设备上弹.
- 其他设备的账转交给所有绑定的设备 (A 绑定了 B 和 C 时, B 也能看到 C 的数据).
- 睡觉时间的两个提示的标记 (`daily.json`, 记哪天弹过) 不同步, 每台设备各自弹一次 (第 19 节).

### 15.3 传输与加密

- **Proxy 断网方式下, 不管名单怎么写, OIT 自己连其他设备的局域网通道都保留**:
  - Windows: 过滤只经过系统代理, OIT 的同步直接走网卡, 不经过代理, 名单管不到它; 4.7 也不会关 OIT 自己的窗口.
  - Android: 只接管 DNS 时局域网本来就直连; 应用名单只管锁定, 不影响联网 (OIT 自己也永远不锁);
    白名单模式离线 (网站白名单为空) 时全部流量进 VPN, 但局域网 / 链路本地 / 广播地址不进 (见 14.2).
  - 例外: Windows 上过滤代理启动失败、程序退回禁用网卡时 (3.2), 局域网也会断, 直到代理恢复.
- 发现: UDP **17931** 端口广播, 发给 255.255.255.255 和每块网卡所在网段的广播地址 (按网卡的真实掩码算; Windows 只从一块网卡发 255.255.255.255).
  同步: TCP **17930** 端口 (被占用时依次尝试到 17939).
- 手机熄屏或 OIT 在后台时, 系统可能暂停它: 这时别的设备连过去能连上, 却等不到回复 (显示"对方没有响应").
  所以绑定了其他设备时, 手机上的 OIT 熄屏也保持 CPU 和 Wi-Fi 醒着, 并申请不受电池优化限制 (8.4). 部分手机 (如 vivo / OPPO) 还要在系统设置里允许 OIT "后台高耗电" / 自启动.
  - 每次打开 / 离开界面时都确认常驻的前台服务在运行 (进程是在后台被系统拉起来时, 当时不允许进入前台, 以前要等重新打开 OIT).
  - 同步线程出错 (例如后台 / 熄屏时界面线程 8 秒没空) 只跳过这一轮, 20 秒后照常再同步 (以前线程会就此退出, 直到重新打开 OIT 都不再同步).
  - 设置 → 基本设置 → **后台运行** 列出 Android 自带的三项限制: 电池优化, 电池设置为"受限", 限制后台数据 (流量节省), 带去解除的按钮;
    以及手机厂商自己的设置页: "后台耗电 (允许后台高耗电)" 和 "自启动" (这台手机上有才显示; vivo / iQOO, 小米, 华为 / 荣耀, OPPO / 一加 / realme, 魅族, 三星, 华硕), 和 OIT 的应用信息页.
    厂商的开关 OIT 查不到是否打开, 需要自己确认.
  - **vivo 等手机不管前台服务, 照样在后台冻结 OIT** (实测 vivo V2168A: 离开 OIT 后别的设备能连上, 却一直等不到回复, 连广播也不回):
    要在 设置 → 电池 → 后台耗电管理 里允许 OIT 后台高耗电.
    正在运行的 VPN 应用系统不会冻结 (否则全机的 DNS 都断了), 所以**开发者模式下绑定了其他设备时, OIT 仍保留一个全部放行的 VPN** (只接管 DNS, 不拦任何东西),
    状态栏照样有 VPN 图标; 没有绑定设备时开发者模式下不开 VPN (同以前). 常驻服务每 5 秒核对一次 VPN 该是什么样, 变了才动.
  - **查得到被冻结过**: 绑定了其他设备时, 常驻服务每秒推进一次; 两次之间隔了 30 秒以上 = 这段时间 OIT 被系统停住了.
    后台运行一栏写出本次运行中被暂停的次数, 最近一次的时间和长度.
  - 绑定了其他设备, 而上面 Android 自带的限制还有没解除的, 或者最近 6 小时里被暂停过: 页面顶部显示红条和"去解除"按钮
    (被暂停过时打开厂商的后台耗电设置页).
- 出错原因显示成看得懂的话: 没有响应 / 对方没在等连接 / 对方已经解除了绑定 / 不是 Proxy 断网方式.
- **设备离线时请它重新启动 OIT** (对方的 OIT 主体还开着但卡住时; 主体关掉了靠联动程序, 15.8): 一台绑定的设备被算作离线 (8.4 的判定) 的当下, 其他设备**立即**向它发一个"重新启动 OIT"的请求 (`POST /oit/v1/restart`, 和别的请求一样加密签名):
  - 连不上 (OIT 没在运行 / 对方卡住) 就每 **30 秒**再发一次, 一旦对方有了回应 (不管是什么) 就不再发; 它回来 (重新有消息) 以后再次离线才再发. 日志 (settings_changes.log) 记 `SYNC restart request to X: HTTP 状态`.
  - **不发**的情况: 本机正在外出 (外出期间的设备不算离线, 8.4); 本机在别的虚拟桌面 (15.7) 或 Adapter 断网 (15.5, 连不上是本机的原因); 对方是关机 (15.4) / 断网 (15.5) / 版本比本机低 (它不认识这个请求) /
    对方明确不接受 (没绑定 / 要先清空 / 它在别的虚拟桌面); 刚打开 OIT 还没同步过一轮 (80 秒) 的设备 (免得把其实在线的设备重启了).
  - 收到请求的设备: 电脑回复之后和更新后重启一样重开程序 (共享的专注不结束, 数据不动); 手机重新打开设备同步 (监听和同步线程) 并重新载入界面. 它在别的虚拟桌面 (15.7) 时不理 (回 `away`).
  - **防循环 / 防误判**: 因为这个请求重启过之后 **10 分钟**之内不再理会重启请求 (回 200 但不动), 免得两台设备互相拉着重启;
    本机刚打开 **90 秒**之内不理 (对方看到的"离线"是本机打开之前的事); 刚和发请求的设备同步成功过 (任何一个方向) **30 秒**之内不理 (本机明明在线).
  - 发请求的一方也一样要先确认**不是自己刚打开才看着对方离线**: 只有本机这次打开之后真的收到过对方的消息 (或者已经打开满 80 秒) 才会发.
- **Windows 防火墙**: 默认拦截入站连接 —— 本机能连别人, 别人却找不到本机, 本机是子端时母端的同步请求也进不来.
  程序启动时在后台补上两条入站规则 (已有就不动), 只放行同一网段 (`localsubnet`) 的连接, 任何网络类型 (专用 / 公用) 都生效:
  `OIT device sync (TCP)` (TCP 17930-17939), `OIT device sync (UDP)` (UDP 17931) 和 `OIT link (TCP)` (TCP 17940, 联动程序, 15.8). 卸载时删除 (9.1).
  以前在"是否允许 Python 访问网络"里点过取消时, Windows 会给 python.exe / pythonw.exe 建**阻止**规则, 阻止优先于允许;
  这些规则也管着别的 Python 程序, OIT 不删, 只在 设置 → 基本设置 → 设备同步的"本机"一行标出它们的名字, 需要在 Windows 防火墙设置里自己删掉或改为允许.
- 绑定时用 Diffie-Hellman (RFC 3526 第 14 组, 2048 位) 交换密钥, 配对码由密钥算出. 之后每个请求都用这把密钥加密 (HMAC-SHA256 生成的密钥流) 并签名 (HMAC-SHA256), 带时间戳, 不接受重放.
  密钥保存在 `sync_state.json` (Android 在应用私有目录里).
- 只用 Python 标准库 / Android 自带的库, 两端是同一套协议 (`devsync.py` / `sync/SyncService.kt`).

### 15.4 关机

一台绑定的设备**收到关机指令**, 或者**电量低于 2%** 时突然离线, 其他设备把它的状态设为 **"关机"**:
效果和正常在线一样, 只是不同步.

- **前提: 它开着开机自启动** (电脑 3.4, 手机 14.8; 每台设备的状态里带着 `auto`). 开机自启动做不到 / 被关掉了的设备, 关机了照旧算**"离线"** (8.4).

- **怎么知道的**:
  - 收到关机指令: 电脑上 Windows 关机 / 注销时 (`WM_QUERYENDSESSION`), 手机上系统关机时 (包括电量耗尽的自动关机, 和部分厂商的快速关机),
    OIT 先存下专注状态, 再马上和绑定的设备同步一次 (最多等 2 ~ 3 秒; 手机是子端时也主动发), 发出的状态里写着"关机".
    电脑上关机被取消 (OIT 1 分钟后还在运行) 时恢复正常.
  - 电量: 每台设备的状态里带着本机电量 (只在用电池、没在充电时; 台式机 / 插着电时不带). 最后一次收到的电量低于 2% (0% / 1%), 之后连不上了 → 关机.
- **效果和在线一样, 不对任何行为造成影响**: 不算离线 —— 合约**不会**因为它"离线超过 15 分钟"失败 (18.1), 专注照常进行,
  Timer 页 / 设备列表里写"关机", 不出现"有设备离线"的提醒.
- **只是不同步**: 它的数据停在关机前最后一次同步; 该由某台设备做的事 (结束专注, 合约的判定 …) 照样在它 2 分钟没同步后由别的设备接手.
- **重新同步上**就恢复正常 (显示它此刻的状态). 版本比本机低的设备 (8.4) 照样算离线, 不算关机.
- **关机的设备重新打开时**: 关机前在专注中 → 专注**照常接着计时**, 就像没关过 ("关机期间专注照常进行"; "还在吗" 照常按开始专注的时刻算,
  过了期限就按 6.6 自动结束). 绑定了其他设备时, 同步上以后跟着它们 (别的设备已经结束了这段就照着切换). 不终止, 不记空闲, 不算纵深推进的违反.
  关机前在休息 / 联网中: 同普通的关掉再打开 (6.3, 2.8).
- **关机期间这台设备的数据不参与专注计时的计算**: 每台设备每 30 秒在数据目录的 `power.json` 记一次"此刻, 算不算关机";
  重新打开时上次是关机 / 没电停下的, 就把 [最后一次记录, 重新打开] 这段记下来 (只在本机, 留 26 小时).
  之后这台设备记下的专注里, 这段**不记** (专注记录在这里断开, 不计入学习时长); 别的设备自己记下的照常算.
  这段时间**只有关机的设备** (没有别的设备记下专注 / 休息) 时, 记为**空闲**.

### 15.5 断网 (电脑换成 Adapter 断网方式)

Adapter 方式离线时整台电脑的网卡都禁用了 (3.1), 没法同步. 绑定了其他设备的电脑换成 Adapter 时:

- **选的时候先警告**: 设置里选 Adapter (绑定了其他设备时) 先弹 "该模式没有正确适配所有功能,你真的要选择这个模式吗?", 取消就改回原来的选项.
- **换之前告诉其他设备**: 网卡还在时先把本机状态设为 **"断网"**, 和每台设备同步最后一次 (最多等 2 秒), 之后**不再同步** (同 15.1, Adapter 下暂停同步).
  其他设备上它显示"断网", **效果和正常在线一样**: 不算离线, 专注不记空闲 (8.4), 合约不会因为它离线失败 (18.1).
  这台电脑自己在断网期间也把其他设备都算作在线 (连不上是本机的原因, 不把自己的专注记成空闲).
- **换回 Proxy 后第一次同步上时**, 断网这段时间两边各自记下的东西:
  - **专注计时有重叠**: 按 **休息 > 专注 > 空闲** 叠加 —— 每台设备只改自己的记录: 被别的设备优先级更高的记录盖住的部分去掉;
    两边一样的 (例如都记了这段专注) 由断网的那台去掉, 不重复计. 去掉的专注同时从学习时长里扣掉. 处理完弹提示写明去掉了多少.
  - **合约的进行时间有重叠** (两边各自开始了合约, 进行中的或已经结束的): 弹窗 "⚔ 合约冲突" 列出两个合约 (起止, 危机等级, 进行中 / 结果, 词条),
    **选一个保留**, 另一个作废: 进行中的直接结束 (不给奖励, 不留记录), 记录里删掉; 作废随同步, 每台设备都一样. 已经给出的休息时间不收回.
    关掉窗口不选的话 1 分钟后再问; 在别的设备上选过了这边就不再问. 正常的交接 (一台结束了合约又开始新的) 不算冲突.
- 手机没有 Adapter 方式 (手机上的"代理-全屏蔽"设置值叫 Adapter, 但不禁用网卡, 照常同步), 只会是另一边.

### 15.6 文件通道 (联网页的"📁 文件通道")

绑定的设备之间直接传文件 / 图片 (走局域网, 和同步一样; 不用联网额度, 离线时也能传).

- **发送**: 联网页右上角 (手机: 联网页最上面) 的 **"📁 文件通道"** → 选一台绑定的设备和一个文件 / 图片 → 发送.
  还没有绑定的设备时提示去 设置 → 基本设置 → 设备同步. 一次一个文件, 最大 **1 GB**.
  发出的是一份签名的说明 (文件名, 大小, SHA-256, 取件码); 对方接收后来取, 取件码 30 分钟内有效. 对方取完时提示"X 已收到 …".
- **接收**:
  - **电脑**: 弹出"📁 收到文件" (谁发来的, 文件名, 大小), 点"保存…"**选择存到哪里** (默认用原来的文件名), 点"拒绝"或关掉就不收.
  - **手机**: 直接收下, 图片存进 `图片/OIT` (Pictures/OIT, 相册里能看到), 其他文件存进 `下载/OIT` (Download/OIT), 存好后提示存到了哪里.
  - 取到后核对大小和 SHA-256, 对不上就删掉, 提示接收失败. 文件名只留名字本身 (去掉路径和不允许的字符).
- **加密**: 内容用绑定时的密钥加密传输 (密钥流: SHA-256(由绑定密钥算出的文件密钥 + 每次随机的 nonce + 块序号)), 说明用同步的方式签名加密 (15.3).
- 对方的 OIT 版本太旧 (不认文件通道) 时提示"对方的 OIT 版本太旧, 收不了文件".

### 15.7 切到其他虚拟桌面 (仅电脑)

- OIT 每 2 秒看一次它的主窗口在不在**当前的虚拟桌面**上 (Windows 的虚拟桌面, Win + Ctrl + ←/→, 任务视图). 用户切到了 OIT 不在的桌面, 这期间**本机算作离线**:
  - 不和其他设备同步, 其他设备发来的同步也不接受 (回"away"); 和普通的离线 (8.4) 一样, 其他设备同步失败 (away 是明确的失败, 马上) / 60 秒没有消息后把本机算作**离线** (不是"关机" / "断网").
  - 离线相关的功能照常执行: 专注里离线的这段记为空闲 (8.4, 两边都是 —— 本机这边其他设备也都 60 秒没有消息, 算作离线),
    Timer 页提示"有设备离线", 合约中离线 (和空闲共用) 累计超过 15 分钟算失败 (18.1) …
  - 切回 OIT 所在的桌面后马上恢复同步, 提示"回到了 OIT 所在的桌面. 切到其他桌面期间本机算作离线.". 切换记进 `settings_changes.log`.
- 只在绑定了其他设备时有影响 (没有绑定的设备时没有"离线"). 把 OIT 的窗口设成"在所有桌面上显示"就不会算作离线. 查不出在哪个桌面时 (系统接口不可用) 照常算在线.

### 15.8 联动程序 (设备离线时替它把 OIT 启动起来)

15.3 的"请对方重新启动 OIT"是发给对方的 OIT 主体的: 主体被关掉 / 崩溃 / 被系统结束了就没有人收. 所以两端各有一个**联动程序**,
是单独的后台进程, **OIT 主体关闭后它照样在**, 负责替别的设备把本机的 OIT 启动起来, 也看着本机自己的 OIT. **不绑定设备时也会启动**.
- **电脑**: `linkd.py` (用和 OIT 一样的 pythonw 运行). 登录时由任务计划程序 `OIT link` 以最高权限启动 (和 `OIT autostart` 一样, 3.4;
  被禁用 / 删掉了就重建, OIT 的开机自启动的任务被禁用 / 删掉了联动程序也一并重建; 每次启动按当前位置重写); OIT 运行时每 **15 秒**确认它在不在 (查本机 17940 端口), 不在就打开.
  程序文件更新后它自己用新代码重新打开. 日志在数据目录的 `link.log`.
- **手机**: 单独进程 (`:link`) 里的前台服务 `LinkService` (通知栏有一条最低优先级的 "OIT link"), 由 OIT 的常驻服务保持它在运行 (不绑定设备时也一样),
  开机 / 更新后由 BootReceiver 打开; 绑定了其他设备时熄屏也保持 CPU 和 Wi-Fi 醒着 (别的设备随时会连进来; 没有绑定就不保持, 省电). 这个进程里没有 OIT 的任何数据和逻辑, 只读 `sync_state.json` (绑定的地址和密钥) 和 `link_state.json`. 日志同样是 `link.log`.
  **从最近任务里划掉 OIT** 时 (实测 vivo V2168A) 系统把 OIT 的所有进程一起杀掉, `:link` 进程也一样, 联动程序帮不上忙. 所以手机上另有一个**保活闹钟** (不绑定设备时也设):
  OIT 运行时每 5 秒把一个 45 秒后的闹钟往后推 (平时不会响); OIT 被划掉后闹钟还在 (只有"强行停止"才会清掉), 约 45 秒后响起 (这之前已经被其他设备算作离线), 把 OIT 的常驻服务和联动程序叫起来, 再设下一个.
  手机被"强行停止"后系统不再运行任何后台组件, 要重新打开一次 OIT.
- **看着自己设备上的 OIT**: 联动程序不只替别的设备收请求, 也每 10 秒看本机的 OIT 在不在 (电脑: 实例互斥体 3.5 或同步端口上有本机的 `hello`; 手机: 主进程在不在或同步端口).
  本机的 OIT **连续 35 秒**不在运行 (同样比 25 秒长: 先让别的设备看到本机离线, 离线时间照常记空闲) 就自己把它启动起来 (启动的方式、`hold` / `cooldown` 的限制同下;
  联动程序自己刚启动 40 秒之内不启动). **有没有绑定其他设备都一样**: 不绑定设备时, 关掉 OIT (包括划掉) 也会被它重新启动 (外出期间除外). 日志里记 `self check: OIT not running for Ns -> started`.
- **更顽强 (电脑)**: 只结束一个进程是没用的, 结束两个也撑不过一分钟:
  - 联动程序和 OIT 互相看着: OIT 每 15 秒确认联动程序在不在, 联动程序每 10 秒确认 OIT 在不在 (35 秒后启动), 结束其中一个另一个会把它拉起来;
  - 联动程序的进程叫 `oitlink.exe` (放在 Python 旁边的 pythonw.exe 的副本; 启动前先试跑一次, 复制不了 / 跑不起来就用 pythonw.exe 本身 ——
    例如 Microsoft Store 版的 Python 就是这样), 在任务管理器 / 命令行里按名字结束 `pythonw.exe` 时它不会一起没;
  - 计划任务 `OIT link` 除了登录时, 还**每分钟**触发一次 (已经在运行时任务计划程序不会再开一个, `IgnoreNew`; 联动程序发现 17940 端口被占就直接退出), 两个进程同时被结束, 一分钟内联动程序回来, 再过 35 秒 OIT 回来;
  - 联动程序每 5 分钟检查自己的计划任务, 被删了 / 被禁用了 / 被改坏了就重建 (OIT 的开机自启动的任务也一样);
  - 服务线程死了 / 出了没想到的异常时在进程里重来, 不退出.
  卸载时先删计划任务, 再关进程 (免得被每分钟的触发再打开), 最后删 `oitlink.exe`.
  手机端: 联动进程也每 10 秒推保活闹钟 (原来只有 OIT 主进程推), 整个应用被系统杀掉后闹钟照样把 OIT 和联动程序叫起来.
- **谁去启动谁**: 每台设备的联动程序每 **10 秒**看一眼每台绑定的设备的 OIT 还在不在 (它的同步端口答不答 `hello`).
  某台设备的 OIT 连续 **35 秒**没答 (比 8.4 "拒绝连接算离线"的 25 秒长: 先让别的设备看到它离线, 再去启动), 就去问**那台设备的联动程序** (TCP 17940, 和同步一样用绑定的密钥加密 + 签名):
  - 联动程序答了 = 那台设备还开着, 只是 OIT 没在运行 (**不是那台设备离线**) → 请它的联动程序启动 OIT;
  - 联动程序也不答 = 那台设备真的关机 / 断网 / 不在这个网络里, 什么都不做 (它开机后会自己启动).
  问了没成 (它的 OIT 还没起来) 每 30 秒再问, 对方回复"已启动"就不再问, 直到它的 OIT 回来后再次不答.
- **收到请求的联动程序**怎么办: 本机 OIT 已经在运行 (同步端口上有本机的 `hello`) → 不理 (`alive`); 本机正在外出 (OIT 把外出的计划结束时刻写在 `link_state.json` 的 `hold_until`,
  外出期间的设备不算离线, 8.4; OIT 关着也照样有效) → 不理 (`hold`); 联动程序自己刚启动 3 分钟之内 (登录时 OIT 的开机自启动正在启动它) → 不理 (`grace`);
  刚启动过 OIT 2 分钟之内 → 不理 (`cooldown`); 否则启动: 电脑先运行任务 `OIT autostart` (最高权限, OIT 已经在运行时任务计划程序不会再开一个), 任务没有 / 被禁用了就直接启动 `main.py`;
  手机启动 OIT 的常驻服务 (主进程跟着起来, 设备同步重新开始). 密钥不对 / 没绑定的设备发来的请求一律拒绝 (403 / 401).
- 这是用户在别的设备上**故意关掉 OIT** 时也会起作用的: 只要另一台设备的 OIT 和联动程序在运行, 关掉的 OIT 约 1 分钟后会被重新打开 (外出期间除外).
- 卸载 OIT (9.1) 时先删联动程序的计划任务、关掉它的进程、删掉 `oitlink.exe`, 再删防火墙规则.
- **代码**: `devsync.py` 只剩装配与自检; `SyncService` 由 `devsync_parts/` 的 7 个 mixin 组成 (`discover` / `pair` / `wipe` / `link` / `docs` / `transfer` / `status`), 常量与纯工具在 `devsync_util.py`, 密码学在 `devsync_crypto.py`; 旧的 `devsync.XXX` 名字都还在 (重新导出).
