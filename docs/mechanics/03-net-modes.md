# 3. 断网方式

[← 返回目录](../../MECHANICS.md)

### 3.1 Adapter (禁用网卡)

- 离线时用 PowerShell 禁用全部物理网卡 (`Get-NetAdapter -Physical | Disable-NetAdapter`), 联网时重新启用.
- 离线期间每隔"断网复查间隔" (默认 **60 秒**, 最少 5 秒) 重新执行一次, 手动打开的网卡会被再次关掉.
- 效果最彻底: 离线时整台电脑都没有网.
- 绑定了其他设备时选它会先警告; 换过去之前告诉其他设备本机"断网", 之后不再同步, 换回 Proxy 后处理重叠, 见 15.5.

### 3.2 Proxy (本地代理过滤)

- 网卡保持开启. 程序在 `127.0.0.1:17890` 启动一个过滤代理, 并把 Windows 系统代理指向它.
  17890 被占用时, 依次尝试 17891 ~ 17910.
- 每个连接按 Rules 页的名单放行或拦截 (第 4 节).
- 过滤只能管住遵守系统代理的程序 (大部分浏览器都遵守). 不读取系统代理的程序过滤管不到, 但发现它直连外面会封锁那条连接 (3.2.3).
- 联网期间也每隔"断网复查间隔"重新检查一次: 代理是否还在运行, 系统代理是否被改回去了.
- 如果过滤代理启动失败, 并且当前是离线状态, 程序会退回到禁用网卡.
- 在 Settings 里切换断网方式时, 程序先让新的方式就位, 再撤掉旧的, 切换过程中不留空档.

### 3.2.1 代理-全屏蔽 (Proxy block-all)

- 和 Proxy 用同一个本地过滤代理 (同样只管住遵守系统代理的程序), 但联网判定**不看名单**:
  离线时除 OIT 内部需要的连接 (本机地址 `localhost`, `127.*`; 设备同步直接走局域网, 不经过代理) 以外,
  所有网站一律拦截, 网站名单和应用名单都放行不了; 联网会话中全部放行. 例外: 专注期间的提前启动程序 (第 20 节) 不拦.
- 网卡保持开启, 所以局域网照常可用, 可以设备同步 (第 15 节); 拦截记录里原因显示为"全屏蔽".
- **只启用应用名单**: 按前台窗口关程序 (4.7) 照常生效, 用哪张应用名单由过滤名单模式 (黑名单 / 白名单) 决定.
  Rules 页只显示当前模式的应用名单 (以及它的等待生效的改动), 网站名单不显示.
- 手机上对应的是"代理-全屏蔽 (Proxy block-all)" (见 14.2).

### 3.2.2 防绕过 (仅电脑, Proxy / 代理-全屏蔽 方式)

Proxy 只管得住遵守系统代理的程序, 所以有两道防线, 防止用户通过启用别的代理 / 关闭代理跳过网络屏蔽:

- **系统代理看守**: 每 **1 秒**看一眼系统代理 (不再只在"断网复查间隔"时看): 被关掉, 改成别的代理 (Clash 之类), 加了 PAC 脚本, 或者绕过列表被改, 马上改回来
  (原来的别的代理照旧记作"原设置", 放行的流量继续转给它, 3.2), 弹一次提示 (30 秒内不重复), 流水里记 `TAMPER`.
- **浏览器围栏** (`browserfence.py`): 给常见浏览器 (Chrome, Edge, Firefox, Brave, Opera, Vivaldi, 360, QQ, 搜狗, 2345, UC, 傲游, IE, Chromium 系) 的程序加 Windows 防火墙
  **出站阻止规则** (`OIT browser fence`, 每个浏览器一条, 按程序路径). 浏览器正常使用时只连本机的过滤代理 (127.0.0.1, 防火墙不过滤本机回环, 不受影响);
  它自己直接连外面 —— 设置里改了代理 / 选了"不使用代理", 插件里的代理, 命令行参数, VPN / TUN 软件接走流量 —— 一律被挡住, 也就绕不开过滤代理.
  每 **10 秒**按正在运行的浏览器和常见安装位置里装着的调整一次 (后台线程); 联网会话中规则照样留着 (浏览器本来就走过滤代理).
  开发者模式, 换成 Adapter 方式, 重置 / 卸载时删掉; 程序启动时先删掉上次留下的.
- 不是浏览器又不读系统代理的程序, 它的直连连接由 3.2.3 发现后封锁。
- 管不住的: 浏览器插件把代理指到本机的另一个代理软件 (回环连接防火墙不管), 以及不读系统代理、只在两次扫描之间短暂直连的程序 (3.2.3).

### 3.2.3 不走系统代理的连接: 封锁 (仅电脑, Proxy / 代理-全屏蔽 方式)

遵守系统代理的程序只连本机的过滤代理 (127.0.0.1), 所以 TCP 连接表里出现"某个程序直接连着外面的地址" = 这条连接不走系统代理 (`bypassguard.py`).
每 **2 秒**看一次 (后台线程), 封锁的是**这条连接**, 不是这个程序:
1. 把这条直连的连接**掐断** (`SetTcpEntry` → `DELETE_TCB`; 防火墙不会切断已经建立的连接; IPv6 的已建立连接掐不断, 只靠下面的规则);
2. 加一条只管"这个程序 → 这个远端地址"的 Windows 防火墙**出站阻止**规则 `OIT bypass block` (`program=<路径> remoteip=<地址>`): 它再连同一个地址的新连接被挡;
   连别的地址不受影响 (发现了再一条一条封); 规则管的那条连接 **10 分钟**没再见到就删掉;
3. **不弹提示**, 只在流水 (`net_requests.log`) 里记 `BYPASS` (每个程序一次).
- 这个程序走过滤代理的部分 (连本机 127.0.0.1) 防火墙不管, 连局域网也不受影响, 所以它的其余网络照常.
- 规则联网会话里也一样 (和浏览器围栏一样, 3.2.2); 换成 Adapter 方式 / 开发者模式 / 重置 / 卸载时删掉, 程序重新打开时先删掉上次留下的 (之后发现了再加).
- **不封的**: 连本机回环的 (连过滤代理, 连本机的另一个代理软件); 连局域网 / 链路本地 / 组播 / 运营商共享地址 (`100.64/10`, Tailscale 之类) 的 (设备同步, 打印机);
  **OIT 自己** (进程和解释器的可执行文件: 检查更新、经上游代理转发 ……); **Windows 自己** (`%SystemRoot%` 下的程序: DNS 客户端, 系统更新, 对时) 和 Windows Defender;
  **用户原来的代理软件** (OIT 接管系统代理之前的代理地址 —— Clash 之类 —— 上监听的那个程序: 过滤代理的流量要靠它转出去; 系统代理关着时也看注册表里留着的 `ProxyServer`, 所以 Clash TUN 的直连不算绕过); `config.BYPASS_ALLOW` 里写的 exe 名 (只有开发版本的 `config_local.py` 改得动).
  `config.BYPASS_GUARD = False` 可以整个关掉 (同样只有开发版本改得动).
- **局限**: 只看 TCP, 只看得到扫描那一刻的连接 (很短的连接可能错过); 程序换一个远端地址重连, 要等下一轮扫描才封 (这之间最多 2 秒, 能连上就能通信一会儿);
  和 OIT 共用同一个解释器的别的 Python 程序不会被封. `python bypassguard.py` 只读列出现在有哪些程序在直连.

### 3.3 启动时

- 程序一启动先断网, 然后按关闭前的联网状态接着申请 / 联网 (2.8).
- Proxy / 代理-全屏蔽 (Proxy block-all): 过滤代理就位后重新启用物理网卡. 上次是 Adapter 方式关闭的, 或者代理起不来退回过禁用网卡 (3.2) 时, 网卡还禁用着.
- Adapter: 禁用网卡, 并还原上次 Proxy 方式留下的系统代理 (否则联网时浏览器仍指向已经退出的过滤代理, 上不了网).


### 3.4 开机自启动 (电脑)

- **默认开启**: OIT 第一次运行时在 Windows 任务计划程序里建一个任务 `OIT autostart`: 当前用户登录时以最高权限启动 OIT
  (OIT 要管理员权限, 放进"启动"文件夹的话每次登录都会弹 UAC). 用电池时也照常启动, 不限运行时长. 数据目录里记下建过 (`autostart_created`).
- **关不掉**: 在任务计划程序里禁用或删掉 `OIT autostart`, OIT 启动时和之后每 5 分钟会把它**重建**并重新开着 (联动程序也会, 见 15.8). 查不了任务 (查询出错) 时不动.
  任务在时, 每次启动 OIT 都按当前的程序位置重写一遍 (程序文件夹搬了家也能启动). 卸载时删掉 (9.1).
- 同样的方式还建一个任务 `OIT link` 启动**联动程序** (15.8; 不绑定设备时也建); 它的任务被禁用 / 删掉了也一样重建, OIT 运行时还会把联动程序的进程打开.
- 开着开机自启动, 是其他设备把本机算作"关机"而不是"离线"的前提 (15.4). OIT 每 5 分钟看一次任务还在不在、开没开.

### 3.5 单实例 (电脑)

- 电脑上**同时只能运行一个 OIT**: 启动时拿一个命名互斥体 (`Local\OIT-main-instance`, `instance.py`), 已经有别的 OIT 拿着就悄悄退出, 不弹窗.
  更新 / 重置后的重新打开: 旧进程马上退出, 新进程最多等 15 秒让它放手.
- **git 仓库里的开发版本不受限** (`updater.is_dev_checkout`, 程序文件夹里有 `.git`): 照常拿互斥体 (联动程序看得见它), 但已经有别的 OIT 在运行时也不退出, 可以和已安装的版本同时开.
  两个版本共用一个数据文件夹 (9.4): 同时开着时两边都在写, 以前会因为写入计数一高一低被对方当成 `rollback` 而**误清数据**; 1.0.467 起写之前按盘上的索引取大的计数 (9.4), 不会再这样, 但最好还是一次只开一个.
- 联动程序 (15.8) 用同一个互斥体判断 OIT 在不在: 有互斥体就不启动 (刚打开、还没开始监听同步端口的也看得见), 再看同步端口上有没有本机的 `hello`.

### 3.6 封闭测试 (开发环境, 仅电脑)

开发版本 (git 仓库里) 用的是真正的数据, 测试时改坏 / 清掉就是改坏了主设备上的数据. 封闭测试 (`closedtest.py`) 把这个实例变成和主设备完全隔开的沙盒:
- **数据全部放在项目根目录**: `closed_test\<程序名>\` (旧版本目录和卸载次数文件也在 `closed_test\` 里), 不读不写 `AppData\LocalLow` 里的数据. 想清掉测试数据直接删 `closed_test\` (已在 `.gitignore`).
- **设备同步整个关掉**: 不监听端口, 不广播, 不绑定 —— 测试数据不会同步给主设备, 主设备的 OIT 也看不见这个实例. 不放行防火墙, 不动合约的防火墙规则 (启动时的清理也不做).
- **不动系统**: 不建 / 不改任务计划程序里的开机自启动 (3.4) 和联动程序 (15.8), 不启动联动程序; 开发者模式自动打开 (不管 `DEV_AUTO`), 开发者模式下不接管系统代理 / 网卡, 关掉程序也不断网.
- **沙盒里照常加密和核对** (1.0.225 起): 封闭测试里 `securefile` (9.4) 和连续性 (9.3) 都是开着的, 但锚点 (`closed_test\_anchors\`, 注册表项 `Software\Obliphur\OIT-closedtest`) 和 `guard.log` 都在沙盒里,
  不碰主设备的锚点, 清数据也只清 `closed_test\<程序名>\`. 所以可以放心地在里面试"数据被倒回去 / 被篡改会被清掉":
  先运行一会儿 (序号在涨), 关掉, 把 `closed_test\<程序名>\` 整个复制一份; 再运行一会儿, 关掉; 用那份旧的覆盖回去再打开 → 弹出"<用户名>,覆水难收.", 沙盒数据被清.
  把主设备的数据复制进沙盒 **不会** 触发: 沙盒的锚点是空的, 复制进来的数据 (同一台电脑 / 同一个用户, DPAPI 解得开) 被当作沙盒的起点; 只有数据解不开 / 比锚点旧 / 被改过才算非法.
  (开发版本本身 — 不是封闭测试 — 仍然不核对.)
- 窗口标题带 `[封闭测试]`, 打开后弹一条提示说明数据放在哪里.
- **打开的办法** (任选其一): `python main.py --closed-test` (`closed_test.bat` 就是这样打开的), 环境变量 `OIT_CLOSED_TEST=1`, `config_local.py` 里写 `CLOSED_TEST = True`.
- 只在开发版本里有效: 公开发布版里 `closedtest.active()` 永远是假. 手机 (Android) 没有这个模块.
