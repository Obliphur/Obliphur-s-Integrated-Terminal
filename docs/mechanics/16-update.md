# 16. 更新 (设置 → 基本设置)

[← 返回目录](../../MECHANICS.md)

两端都从 GitHub 仓库 [Obliphur/Obliphur-s-Integrated-Terminal](https://github.com/Obliphur/Obliphur-s-Integrated-Terminal) 的**最新发布 (Release)** 检查更新.

- **打开时检查更新** (默认开启): 每次打开程序时检查一次 (电脑: 程序启动后约 3 秒; 手机: 每次打开界面).
  检查失败时 (例如没有网), 电脑在下一次联网会话开始时再查, 手机在下一次回到界面时再查.
- **自动更新** (默认开启): 发现新版本时自动下载 —— 电脑直接安装, 提示"立即重启"; 手机下载好安装包后弹出提示, 点"安装"打开系统的安装界面 (Android 一定要用户确认).
  电脑上点"立即重启": 旧窗口马上隐藏, 保存和收尾做完后关掉 (收尾中途出错也照样关掉), 打开新版本后旧进程立即退出, 不会留在后台.
  关闭自动更新时, 发现新版本只弹提示, 按"立即更新"才下载.
- 两项都是即时生效, 不同步给其他设备. 也可以随时在"⬆ 更新"一栏按"检查更新".
- **版本号**: 发布的名称里有 `1.2` / `1.2.0` 这样的版本号就用它, 否则用标签 (`v1.2`, `1` …) 里的数字; 比本机的版本 (电脑 `config.APP_VERSION`, 手机 `versionName`) 新才算有更新.
- **电脑**: 发布里有名字带 `windows` / `win` / `pc` / `python` 的 `.zip` 附件就下载它, 否则下载这个标签的源码压缩包.
  解压后把程序文件覆盖到程序文件夹 (跳过 `Android version/`, 不删除多出来的文件, 不碰数据目录), 重启后生效.
  程序文件夹是 git 仓库 (开发用的副本) 时不覆盖, 只提示用 `git pull` 更新.
   内容没变的文件不覆盖; 有变化但正被占用的资源文件 (例如 OIT 自己私有加载着的像素字体, 覆盖会报 WinError 32) 跳过留到下一次, 只有被占用的 `.py` 才算失败. 程序里不要长期占着随程序发布的文件 (指令页的音效放完就关掉).
- **手机**: 下载发布里的 `.apk` 附件 (优先名字带 `release` / `android` 的); 发布里没有安装包时只提示有新版本.
  第一次安装更新时 Android 会要求允许 OIT "安装未知应用".
  新安装包必须和手机上已装的 OIT 用**同一个签名**, 否则系统会拒绝安装 (需要先卸载旧版).
  **开发版 (本地构建, 有开发者模式的那种) 不会更新成发布版** (1.0.234 修复: 以前点"立即更新"总是更新成正常版): 检查更新只记下最新的发布版本号, 状态是"开发版", 不下载、不安装; 其他设备发来的安装包拒绝 (回复 `dev`), "让其他设备发来"也不可用. 开发版要换版本就用 adb / 本地构建安装. 它仍可以把发布版的安装包发给别的设备.
- **直接发给其他设备** (绑定了其他设备时, 第 15 节): 任意一台设备都可以替别的设备从 GitHub 下载安装包, 直接从局域网发过去, 对方不用自己去 GitHub 下载 (例如手机上不方便连 GitHub).
  - 同步时每台设备报上自己的版本. 自动更新开着时, 发现绑定的设备比 GitHub 上的最新版本旧, 就给它下载对应平台的安装包 (电脑: 同上面的 zip; 手机: apk) 并发过去, 每台设备每个版本发一次;
    也可以在"⬆ 更新"一栏按"📤 发给其他设备"手动发 (结果逐台显示).
  - 发送方先发一份签名的说明 (平台, 版本, 大小, SHA-256, 一次性取件码), 接收方确认是自己的平台, 而且比自己的版本新, 才去发送方那里取文件 (最大 160 MB, 30 分钟内有效),
    取完核对大小和 SHA-256, 对不上就丢掉.
  - 接收方收到之后和自己下载的一样: 电脑在自动更新开着时直接安装, 提示"立即重启", 否则先问; 手机弹出提示, 点"安装"打开系统的安装界面. git 仓库里的开发版本不收.
  - **让其他设备发来** (反过来请别人发, 手机上): 手机连 GitHub 下不动时 (例如电脑开着代理, 手机没有), 按"📥 让其他设备发来",
    或者手机自己下载失败时自动请一次: 向每台绑定的设备发一个签名的请求, 对方 (不管它的自动更新开没开) 给这台手机下载 apk, 再按上面的方式发过来.
    对方的 OIT 太旧不认这个请求时提示"版本太旧". 收到后手机自己还在进行的下载自动取消.
- 只连 GitHub 的 https 地址, 跳转也只能跳到 GitHub 的下载地址.
  电脑上不经过 OIT 自己的过滤代理, 所以 Proxy 方式下不管名单怎么写都能检查; Adapter 方式离线时网卡被禁用, 检查会失败.
- **下载路线** (两端相同): 安装包走 GitHub API 的附件地址 (`api.github.com/…/releases/assets/<id>`), 它直接跳到下载服务器 (release-assets.githubusercontent.com),
  不经过 github.com —— 有的网络里 github.com 连不上, api.github.com 和下载服务器却能直连, 所以**不用开自己的代理**. 电脑版没有 zip 附件时用的源码包走 api.github.com → codeload.github.com.
  下载完核对大小和 GitHub 给的 SHA-256, 对不上就丢掉; 下载失败时不留下半截的文件.
  电脑上直连连不上 (超时 / 拒绝) 或回 5xx 网关错误 (502 / 503 等) 时, 再经过原来设的代理 (Clash 之类, OIT 接管系统代理前的设置; 系统代理关着时也看注册表里留着的 ProxyServer) 试一次.
  手机上走 Wi-Fi / 移动数据本身, 不经过 OIT 的 VPN.
  手机上下载时显示进度 (已下载 / 总大小, 速度, 重连次数), 可以"取消下载". 下载 20 秒后还很慢 (不到 200 KB/s) 时, 同时请绑定的设备发来 (见上面"让其他设备发来"), 谁先到用谁. 连接断开或卡住 (30 秒内收不到 64 KB) 时自动重连, 接着已下载的部分继续 (Range);
  连着 4 次没有进展才算失败, 失败后可以"重新下载".
- **多连接下载** (1.0.273, 两端相同): 下载服务器对**每条连接**限速 (国内不开 VPN 时每条 40 KB/s 上下, 20 MB 的安装包一条连接要 8 分钟), 但连接条数越多总速度越高
  (实测不开 VPN: 1 条 ≈ 0.04 MB/s, 16 条 ≈ 0.6 MB/s, 32 条 ≈ 1 MB/s; 20 MB 的 APK 约 20 秒). 所以知道大小的附件 (APK / setup.exe / zip, 1 MB 以上) 这样下:
  先请求第 0 个字节 (顺便走完 API 的跳转, 拿到下载服务器上带签名的地址, 确认服务器支持 Range 而且总大小和 GitHub 给的对得上), 再切成 256 KB 一段, 同时开 32 条连接各取各的
  (Range, 要回 206 而且起点对得上, 写进预先开好的文件的对应位置). 一段失败换新连接重试 3 次, 还不行, 或者服务器不支持 Range, 就退回上面的一条连接 (断了接着下).
  下完照样核对大小和 SHA-256. 电脑上走的路线 (直连 / 原来的代理) 和请求第 0 个字节时走通的那条相同; 手机上进度 / 速度 / 取消照常 (所有连接合计),
  30 秒内合计收不到 64 KB 算卡住. 源码包 (电脑版没有 zip 附件时用的) 是 GitHub 边打包边发的, 没有大小也不能分段, 还是一条连接 (约 2 MB, 不开 VPN 时 40 秒上下).
- 发布新版本时 (`release.py` 做, 附件是手机的 `OIT.apk` 和电脑的 `setup.exe`, 见 16.4): 先改两端的版本号 (`config.py` 的 `APP_VERSION`, `Android version/app/build.gradle.kts` 的 `versionName` 和 `versionCode`), 发布的名称写版本号, 附上 APK (和可选的电脑版 zip).
  本机发布脚本的 `git fetch` 和 GitHub API / 附件上传不经过 OIT 的过滤代理: 通过仅放行当前 GitHub HTTPS 主机的本机隧道, 由发布脚本进程转发, 避免 Git 子进程的直连被防绕过守卫封锁. 先直连, 失败后走用户原来的代理; 系统代理关着但仍留着 `ProxyServer` 的 Clash TUN 同样识别. API 的 408 / 500 / 502 / 503 / 504 响应会换路线重试, 401 / 403 等权限错误直接返回. Adapter 方式离线时仍不能发布.

### 16.4 安装程序 setup.exe (电脑版)

发布 (Release) 里除了手机的 `OIT.apk`, 电脑版以一个 **`setup.exe`** 提供 (`setup.py` + 程序文件打成 `payload.zip`, 用 PyInstaller 打包成一个 exe, `release.py` 编译并上传). 它做的事:
- **依赖库**: OIT 本体是 Python 程序, 需要 Python 3.10+ (带 tkinter 等标准库). setup 先找电脑上有没有 (注册表 PEP 514 / `py -0p` / PATH, 挑版本最高且能 `import tkinter, sqlite3, ssl, ctypes, winreg` 的);
  没有就从 python.org 下载官方安装包 (固定版本 `PYTHON_VERSION`), **核对数字签名有效且签名人是 Python Software Foundation 才运行**, 静默安装 (所有用户, 不改 PATH, 不装 py 启动器, 不抢 `.py` 的关联).
  可选库 pywin32 用 `pip install` 装 (OIT 没有它也能用, 装不上只提示; 界面里可以取消勾选). 找到的 / 装好的 Python 记在 `install.json`.
- **安装**: 程序文件 (git 里跟踪的, 不含安卓版) 复制到安装位置 (默认 `C:\Program Files\OIT`, 可改) 并预编译 `.pyc`. 同一个位置再装一遍 = 升级, 数据 (在 `AppData\LocalLow`) 不动.
  OIT 正在运行时不装 (关闭 OIT 会断网 / 恢复网络, 实例互斥体见 3.5), 提示先退出; 升级也可以用 OIT 自带的更新 (上面). 目标文件夹是 git 仓库 (开发版本) 时拒绝.
- **注册成软件** (`registration.py`): 在 `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\ObliphurIntegratedTerminal` 写名称, 版本, 发布者, 安装位置, 图标, 大小,
  卸载命令 (= 装时记下的 pythonw 运行 `uninstall.py`), 于是 设置 → 应用 → 已安装的应用 里有 OIT. 可选桌面 / 开始菜单快捷方式 (当前用户的, 名字 `OIT.lnk`, 和第一次打开时介绍窗口里的是同一个).
  装完可以直接打开 OIT (setup 已是管理员, 不再弹 UAC).
- **之后**: OIT 每次启动时 (`registration.refresh`) 把"已安装的应用"里的版本号改成现在的 (程序自己更新过版本会变), 注册信息被清理工具删了就补上. 用 setup 装的程序文件夹里有 `install.json`, 其他方式 (解压 / git) 没有, 这些都不会发生.
- **卸载**: 从"已安装的应用"点卸载就是运行 `uninstall.py` (9.1); 对 setup 装的, "同时删除程序文件夹"默认勾上, 并且会删掉 setup 建的快捷方式和上面那条注册信息. 装的 Python 不动 (别的程序可能在用).
- **图标**: `oit.ico` / `oit.png` 由 `make_icon.py` 画出来 (纯几何: 蓝色圆角方块 + 缺口的计时圆环 + 终端提示符 `>_` + 琥珀色圆点, 没有位图素材), 同一份几何也生成手机的启动图标
  (`ic_fg.xml` 前景 + `ic_bg.xml` 渐变背景, 自适应图标) 和通知栏的单色小图标 (`ic_stat.xml`). 用在: OIT 的窗口 / 任务栏 (进程用单独的 AppUserModelID, 不和别的 Python 程序混在一起),
  桌面 / 开始菜单快捷方式, "已安装的应用" 里的图标, setup.exe 自己. 改图标就改 `make_icon.py` 里的常数, 再运行 `python make_icon.py`.
- **命令行**: `setup.exe /S` 静默安装 (日志在 `%TEMP%\oit-setup.log`), `/D=路径` 指定位置, `/nodesktop` `/nostart` `/nopython` `/nopip` `/run`.
- 注意: 自己打包的 exe 有时会被杀毒软件误报; 也可以不用 setup.exe, 照旧解压源码 / 压缩包后 `python main.py` 运行.
